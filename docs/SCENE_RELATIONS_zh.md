# 场景关系监督与分支关系

本轮目标是北京时间 2026-10-25 16:00 前给出实现、真实数据验收和可评估的小实验。它不是对完整指标显著改善的承诺，最终论文仍需完整验证与独立测试。

预定 24 家族试验现已完成：独立无场景 124.6771、原场景修复 122.9634、新关系监督 122.8286、同一新模型错配场景 123.0071 mm。相对父模型仅改善 0.1347 mm，正确/错配仅差 0.1785 mm；空场景与独立无场景逐窗指标完全一致。原 176 窗口扩大验证随后完成：无场景 114.3403、原修复 112.0542、新方案 112.1088 mm，新增监督略差。当前不支持“具体场景利用明显增强”的结论，不替换原主模型。小集和扩大验证表分别见 `runs/scene_ego128_relations/evaluation/recovered/REPORT_zh.md` 与 `evaluation/quick/REPORT_zh.md`，不能混用两套窗口数值。

当前决策是保留原已选场景修复权重，不因小集很小的 MPJPE 改善替换主模型或扩大关系监督训练。176 窗口已完成，接下来完成保守无场景额外预算对照。进一步候选应处理推理时的几何信息路径：当前局部 token 的法向、表面距离可靠性等预留特征仍为零，本轮 PCA 只用于损失分支；可评估从真实观测点估计平面方向与置信度并输入局部修正器，同时保留退化邻域拒绝和空场景回退。这是待验收的实现方向，尚未训练或证明有效。之后仍需动作输入相同、参数量与更新预算匹配的无具体几何修正器对照，防止把额外修正容量当场景收益。

保守无场景对照的 1k 验证曾因缺少 `evaluation/quick/` 目录而未保存指标，原权重和优化器已保存；未把丢失的指标报告为已完成。已补齐目录、保留完整 1k 恢复点，按原封印代码精确恢复 AdamW/RNG 继续到固定 3k，当前 PID 及实时进度见其 `training/STATUS.json`。恢复共享已获用户对 clip2 VideoMimic 任务的明确授权；人工核实同视频、同流水线父进程从 VIMO 进入重建阶段后绑定完整当前身份，未放宽未知任务拒绝规则。

## 为什么要验证这个候选方案

正确场景与同类错配场景在 176 窗口上的主指标分别为 112.0542、112.2274 mm，差异不明确。平均误差相近不等于输出完全相同；同动作类别的错配也可能保留相似支撑结构。因此还要报告输入几何差异及预测关节变化，不能只看平均 MPJPE，也不能故意把错误场景训坏来制造差距。

当前 `contact_logits`、`correspondence_logits` 门控没有独立几何监督，靠动作损失间接学习；这一事实不能单独证明退化原因。新试验给这些门控明确但保守的弱几何标签，并直接监督人体与表面的关系。

## 三数据集统一定义

- 真实观测使用相机的历史静态点与当前帧表面点，不加入未来历史或隐藏全场景网格。训练仍沿用原协议中已审计的 400 条完整椅子合成条件增强；这些必须标为合成观察条件，不能称为原相机实际看见。验证禁用该增强。
- 对原生 SMPL、SMPL-X、G1 使用同一 67 个人体皮肤锚点接口。模型预测使用预测体形；真值原生体形与动作只在损失分支重建监督锚点。
- 从观测点的局部邻域估计无向平面。至少 6 点，要求二维铺展、低平面拟合残差且属于最近的同一物体；退化、混合物体和无证据区域不监督。这个法向不代表封闭网格的内外方向。
- 匹配预测与真值相对该表面的法向间距，而不是要求每个脚点距离为零；真值离表面 8 cm 时，损失不会强迫预测点贴面。切向运动仍由原动作目标约束。
- 门控标签来自近表面程度及冻结动作提议与监督表面的对应关系，只是弱几何标签，不是金标准接触、座椅语义或 BSTRO 标签。
- 只训练局部表面编码、局部条件和反馈模块，动作、体形、相机和全局场景路径冻结。保留原有动作、相机及相对无场景提议的一致性目标。

因此损失实现不包含“坐下”“楼梯”等动作类别条件，也不要求完整椅子、封闭网格或人为落脚点。沿用的完整椅子训练增强属于原数据协议，不能单独归为新增通用损失的收益。观测稀疏或原始动作/场景错位仍会造成监督缺失；覆盖率必须按三个数据集报告。

## 小实验与验收

配置在 `configs/scene_relations.yaml`，通用损失在 `scenemi/geometry/observed_relations.py`，入口为 `scenemi.scene_relations`。先做 CPU/CUDA 真实三数据集验收：目标标签污染不改变推理输出、空场景等于冻结先验、几何监督有覆盖、门控获得梯度、冻结权重不变、优化器及 RNG 精确恢复。通过前不启动试验训练。

固定 500 更新、batch 8、重置优化器、学习率 2e-5，只保留一份原子 `last.pt`。训练数据仍为三个数据集等权、不加 RICH；父权重与源代码封印单独记录。该阶段不是把旧场景版继续训练，也不是重新从 AMASS 开始。

预先用 seed 20261025 从原 176 窗口中选每数据集 8 个独立家族，共 24 个窗口；GRAIL 覆盖五类。固定最终 500 步，不在这 24 例上挑 checkpoint。最终评正确/空/错配场景，并与父权重同窗口指标配对，同时记录几何输入覆盖、占据交并比、局部表面差异与预测关节位移。它是试验读数，不能替代原 1416 窗口比较或独立测试。

运行时复用原资源准入、UID/cwd、未知 PID 拒绝及 cgroup；仅在新入口进程内注册新增 SceneMI 模块，不修改已有运行器。显存分配上限 6GiB、RAM 8GiB、两 CPU。

```bash
python -m experiments.offline_camera_retrain_v1.ops.resources run \
  --device cpu --memory-gib 8 --cpu-count 2 -- \
  python -u -m scenemi.scene_relations preflight --device cpu

python -m scenemi.shared_runtime run --device cuda \
  --memory-gib 8 --cpu-count 2 --allocator-gib 6 -- \
  python -u -m scenemi.scene_relations preflight

python -m scenemi.shared_runtime run --device cuda \
  --memory-gib 8 --cpu-count 2 --allocator-gib 6 -- \
  python -u -m scenemi.scene_relations train
```

结果目录：`runs/scene_ego128_relations/`。配置、验收、开始训练、试验读数和完成完整评测应分别报告，不能混称“方案已有效”。

## 已完成的只读几何核验

24 个预定验证窗口的原生真值骨架重建最大偏差为 1.19e-7 m，SMPL/SMPL-X/G1 坐标与监督骨架一致。它是损失分支核验，不是推理提供真值体形。

| 数据集 | 有任意可信平面监督的窗口 | 足部锚点的平均可信平面覆盖率 | 臀部锚点覆盖率 |
| --- | ---: | ---: | ---: |
| EgoBody | 3 / 8 | 16.41% | 2.60% |
| TRUMANS | 8 / 8 | 83.17% | 3.91% |
| GRAIL | 8 / 8 | 48.40% | 1.56% |

这些是预定小集与当前保守局部平面判据下的覆盖率，不能外推为全数据集可见率。它已表明有效关系证据很不均匀，臀部附近尤其稀疏；仅增加注意力层数不能补回没有观测的表面。后续应分别报告有/无可用观测区域的诊断，同时保留不筛选的完整主指标。资产可用也不等于每个局部表面已被相机观测。

CPU 三数据集真实更新、标签隔离、空场景精确回退、局部门控梯度及精确恢复均通过，共训练 2,053,128 个局部参数。首次读取 SMPL 资产时发生缓存读异常；文件级刷新后连续三次映射读取与一次缓冲读取均恢复原 SHA，未修改资产或系统缓存策略。

用户随后明确批准与本用户 VideoMimic 重建进程共享 GPU。当前新 CUDA 验收与开训使用 `scenemi.shared_runtime`，授权身份封存在 `GPU_SHARING_AUTHORIZATION.json`；原场景/无场景模型与运行器源码均不改。

## 额外无场景预算对照的纠正

首条 `scene_ego128_noscene_continue` 在原 30k 末期 LR 5e-6 的基础上重置优化器并重启至约 1e-4。额外 1k 的 176 窗口主指标从 114.3403 变为 212.5687 mm，明显退化。该分支已在额外 1188 步安全停止并保存；其原协议、逐窗指标和 `CONTROL_REVIEW.json` 保留，不能把这个退化对照用于声称场景有效。它不代表所有无场景续训都会退化。

替代设置 `configs/scene_noscene_continue.yaml` / `scenemi.continuation` 从原独立无场景 30k 重新出发，严格装载原权重、AdamW 动量和全部 RNG，保持 checkpoint 末期 LR 5e-6，不重启 warmup。再训练固定 3k，每 1k 记录原 176 窗口，最终 3k 评原 1416 窗口。只覆盖一份 `last.pt`，不做有利 checkpoint 搜索。它仍是同额外步数的验证对照；场景 3k 是经 8k 搜索选出的，不能称最佳对最佳或独立测试结果。

新的对照输出为 `runs/scene_ego128_noscene_low_lr/`，与原高 LR 分支分开。16:00 前的优先交付是场景候选验收和预定小集试验；3k 加完整 1416 窗口的对照需要更长时间，不能预先保证该时刻完成。

该对照现已通过 CPU/CUDA 真实验收并启动，CPU 亲和性为 16、17；局部场景试验为 18、19，均受原两 CPU 限额约束。被否决高 LR 分支的权重仍保留：自动审批拒绝永久删除四个具体权重路径，没有执行删除。

即便局部监督试验改善，论文还应检查“同容量但不使用具体场景的动作修正”对照，区分额外可训练容量/动作先验适配与具体几何信息的作用。正确/空/错配只是固定权重干预，不能替代这一训练消融。新候选的几何损失本质上是按可观测表面方向和置信度加权的动作监督；它不会在理论上保证网络必须利用具体场景，仍需用敏感性与匹配对照验证。

为解决反复的旧缓存读取异常，新的两个入口使用已有的严格 SHA 重读路径，并从已封印完整 checkpoint 恢复其保存的原生人体/皮肤基。不是更换人体资产或接受新 SHA。新场景入口逐张量核验完整父状态，且在 CUDA 上复现父模型三个数据集的原 DDIM 指标；CPU 仅作本设备采样检查，因为同 seed 的 CPU/CUDA Gaussian RNG 不同。修订前的准备与验收证据保存在 `preparation_attempts/`，没有回写已完成实验。

500 步训练已完成并保存。原评测完成 24 个窗口推理后，在 `dict(rows=..., **aggregate_scene_rows(...))` 汇总处遇到重复 `rows` 参数，未写出结果。训练状态中的 `failed` 指这次后处理失败，不代表训练中途停止。保留原源码与失败记录，改由独立的 `scenemi.relation_evaluation` 读取同一最终权重；汇总回归检查已通过。新入口逐例保存指标、配对预测及哈希，重跑同一预定 24 窗口，再追加原 176 窗口正确场景验证，不选新 checkpoint。恢复评测状态及结果在 `evaluation/recovered/`，扩大验证在 `evaluation/quick/`；两者都不是独立测试。
