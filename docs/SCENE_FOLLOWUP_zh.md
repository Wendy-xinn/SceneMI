# EGO-only 场景收益核验

入口为 `python -m scenemi.scene_followup`，配置 `configs/scene_residual_followup.yaml`。这是前一轮冻结先验实验之后的独立检查，不改已完成实验源码、数据、权重或指标。

## 固定权重场景干预

锁定最终复评选定的 3k 场景适配权重，完整复用原快集 176 个窗口、seed 777、DDIM 20。正确场景和独立无场景指标引用带哈希的原逐窗记录，三个数据集各至少一个窗口现场复现。另对每个窗口运行空场景和错配场景；错配场景从同一数据集、同一动作类别的其他来源家族选取，全部几何字段共同替换，人体/相机条件不变。用家族配对差异核验，不当作独立训练消融。

依预先固定种子为 GRAIL 五类动作各选两个独立家族，保存同窗正确场景、独立无场景、目标动作和 rest，用于后续几何核验；选择不读取预测误差。

输出：`runs/scene_ego128_residual_checks/STATUS.json`、`RESULT.json`、逐窗 ledger、10 例配对数组。每条干预身份和错配来源均可追溯；中断末行归档后续跑，数组原子写入。

## GRAIL 几何诊断

仅在上述 10 例上，使用公开固定 G1 输出模板重建完整足部与后臀皮肤子集。三种动作分别通过 FK/坐标闭环验证，首例还核对完整 SMPL-X LBS。完整源场景只用于评分，不进入模型输入。

三种动作共用根据目标动作与真实支撑几何确定的稳定支撑帧代理，报告足部到地形的 q10 距离、浮脚比例、水平滑动速度、地下穿透和闭合物体内部深穿透。座面报告目标稳定坐姿且确有座面支撑时的距离。目标重建本身的几何误差也保留。开放物体不声称有符号体积穿透；这些代理不是经过验证的接触真值，也不代表完整足底/座面接触面积。

输出：同目录 `GEOMETRY_STATUS.json`、`GEOMETRY_RESULT.json`。这是按预定规则抽样的诊断，不替代完整验证集主指标或独立测试。

## 额外训练预算对照

从与场景修复完全相同的独立无场景 30k 权重出发，再训练 8k；仅 EGO，EgoBody/TRUMANS/GRAIL 等权、128 帧、batch 8，沿用场景修复的学习率、warmup、数据采样种子和两阶段选模覆盖。个人体形由允许输入预测，不用 RICH、真值个人体形或 test。

这条分支继续更新原无场景网络及体形适配，没有场景字段进入推理 payload。它用于检验“额外优化是否也能带来提升”，不是冻结修正模块的参数量/损失完全匹配消融；不能把它当成唯一的几何因果证据。零步须复现父权重的全部 176 窗口，CPU/CUDA 真实批次、几何/标签污染不变性和优化器/RNG 精确恢复通过后才训练。沿用每 1k 候选和快集前三加最终候选的 1416 窗口复评。保留零步候选，若继续训练退化则如实报告。

输出：`runs/scene_ego128_noscene_continue/`。同一额外步数和各自选定候选都应比较，明确最优候选不一定在终点。每份候选保留到评测审核；启动前按实际 checkpoint 大小检查候选空间及 20GiB 磁盘余量。

## 串行执行

`run` 在同一受限任务中依次运行干预、几何核验、CPU/CUDA 对照验收及对照训练；任一步失败停止并记录，不自动修改协议或启动 EXO。主状态为 `runs/scene_ego128_residual_checks/PIPELINE_STATUS.json`。

```bash
SCENEMI_ALLOCATOR_GIB=8 python -m experiments.offline_camera_retrain_v1.ops.resources run \
  --device cuda --memory-gib 12 --cpu-count 2 -- \
  python -u -m scenemi.scene_followup run
```

继续使用独占准入和进程内 8GiB 分配上限；不改既有共享运行器或干预其他任务。`budget-preflight` 与 `budget-train` 可分阶段调用，恢复时只用已封印的代码与配置。

## 已完成的输入干预与当前优先级

176 窗口干预已完成：正确场景 MPJPE 112.0542、空场景 114.3403、同数据集/动作类别的其他家族场景 112.2274 mm。正确场景比错配场景好 0.1732 mm；该成对差异的 95% 家族重采样范围跨零。当前检查不足以证明模型充分依赖匹配的具体几何；同类场景仍可能共享有效支撑结构，也不能据此断言模型完全忽略场景。不能把“场景存在时优于空输入”直接当成几何推理证据。

GRAIL 10 例几何检查也已完成，但仅作诊断；足底距离、滑动和座面结果并非一致改善。模型仍是三个数据集共同训练、原生 SMPL/SMPL-X/G1 解码；仅诊断实现先支持了 G1，不代表模型仅能用于 GRAIL。

EgoBody 45/45、TRUMANS 33/33 验证录制已核实有原始静态网格；证据在 `docs/validation/native_scene_geometry_availability.json`。这只是资产可用性核验。三数据集统一几何诊断还需预测体形的皮肤重建、开放网格与法向可靠性、动态物体逐帧变换的验证。不能将缺失或不可判定的几何项算零。

下一项场景训练改动应使用通用的“人体部位—已观测局部表面”关系，分别考虑表面距离、可信接触时的切向速度、可靠几何下的穿透与观测置信度。避免按 GRAIL 的椅子或楼梯类别设计专属规则；监督仅在已观测、可靠的区域生效，未知处保留先验。保持原主指标并按三个数据集分别报告；跨数据集评测与未见场景/物体泛化仍需单独支持。

## 优先复评无场景 3k

保留正在运行的 8k 学习率调度，在其 3k 候选原子保存后，以原 1416 窗口单独完整复评，并与场景 3k 配对。入口为 `python -m scenemi.scene_checks watch|evaluate`，固定策略在 `configs/scene_checkpoint_3k.json`。这是同额外步数比较；场景 3k 是在 8k 候选搜索后选出的，最终最佳对最佳比较仍需同等候选搜索预算。

CPU watcher 仅等待本用户的固定候选，GPU 子任务复用 `parallel_resources` 的原准入、UID/cwd 检查及 cgroup，显式注册 `scenemi.scene_followup` 与 `scenemi.scene_checks` 两个新入口；显存分配上限 6GiB、RAM 8GiB、两 CPU。未知 GPU 任务或资源不足时停止，不自动绕过或排队等待其他用户。当前训练源码与配置封印不改。

结果和等待状态：`runs/scene_ego128_noscene_continue/evaluation/step_003000/`。无需等 8k 最终选模结束才查看 3k 对 3k 的结果。

## 可迁移的场景约束应满足什么条件

3k 先作同额外更新步数的阶段对照，不将它重新解释为已知最优训练长度。保留原 8k 调度，不能临时缩成 3k 的余弦调度后声称训练条件相同。

| 项目 | 三数据集共用定义 | 当前状态 |
| --- | --- | --- |
| 人体与表面关系 | 使用预测原生体形重建的人体部位，查询已观测表面的距离、方向及覆盖置信度 | 原有局部反馈有共同接口；新增关系监督未启用 |
| 支撑与滑动 | 只在可信支撑期间评价/约束切向滑动，不强迫摆动脚贴地 | GRAIL 小样本诊断已完成，其他两数据集待坐标与网格核验 |
| 穿透 | 仅对法向或内部判定可靠的几何使用相应指标；开放、未知区域标记不可判定 | 不将开放扫描强行当封闭体 |
| 场景是否被使用 | 固定动作/相机，比较正确、空、错配场景 | 176 窗口完成，正确对错配差异很小，尚不能证明充分利用具体几何 |

训练监督若使用真值动作或离线几何，必须与推理可见输入分开记录。不能把未观测的完整椅子加入正常相机设定的输入，也不能用吸附、下压或按动作类别修正来代替学习。泛化证据需要至少三个数据集分别报告；未见场景与跨数据集的结论还需要相应留出实验。

## 训练恢复记录

无场景额外更新对照在 292 步因 Windows 盘 9P 读取时的内核内存分配失败退出，未出现 CUDA 显存不足。未完成更新尾部保留，恢复从完整的 0 步检查点重放。使用独立 `budget-train` 进程，复用通过的 CPU/CUDA 验收与原 83 文件封印；8GiB 分配上限、12GiB RAM、两 CPU、数据和优化调度均不改。原串行流水线失败状态保留，独立恢复状态见 `runs/scene_ego128_noscene_continue/recovery/RESUME.json`，实际训练以该分支 `training/STATUS.json` 为准。

该高学习率重启分支后来因明显验证退化在额外 1188 步停止，不能用它证明场景收益。原流水线失败快照归档到 `history/original_sequential_failure.json`；根 `PIPELINE_STATUS.json` 现为后续实验快照，明确列出真实子状态路径，不代表旧 PID 仍在运行。新的观测关系监督试验和保留原优化器/低 LR 的无场景对照见 [分支关系与当前方案](SCENE_RELATIONS_zh.md)。
