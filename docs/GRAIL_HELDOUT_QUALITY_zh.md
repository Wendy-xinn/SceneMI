# GRAIL val/test 动作与场景质量检查

用户于 2026-10-26 要求对 GRAIL val/test 同样检查动作与场景的对齐。此前这两部分只核对了导出身份、长度及原始家族划分，没有执行训练时的接触/脚底支撑筛选。本次检查源动作、接触估计和场景几何，不执行模型推理，不读取模型预测来决定筛选，也不调整阈值。

## 固定规则

配置为 [grail_split_quality.json](../configs/grail_split_quality.json)，逐项复用已有的 [接触规则](../configs/grail_ego_contact.json)和[脚底支撑规则](../configs/grail_ego_support_v2.json)：

- 估计接触概率大于 0.8 时，检查脚底悬空；检查持续双脚悬空、明显穿透及接触时滑脚。
- 脚底取脚部最低 15% 顶点，仅向下检测 `abs(normal_y) >= 0.7` 的面；间隙 3 cm 内至少有 20% 顶点得到支撑。检查持续双脚无支撑和估计站立脚无支撑，避免将台阶立面当作支撑面。
- 坐姿沿用接触规则中的坐面距离、穿透、稳定坐姿和支撑面检查；不要求脚同时接地，不添加合成椅子。
- 原接触/支撑事件需持续至少 8 帧，前后各扩展 6 帧；源数据标记的无效帧也不能进入选中片段。
- 仅保留完全不经过这些坏帧的连续 128 帧片段。不会把坏帧两侧的动作拼接；某个干净片段若不足 128 帧，也无法被当前模型抽取。

相机可见性与动作几何质量分开：本次记录 EGO 物体可见帧数，但不因人或交互物体出画而删除干净动作监督。EXO 和 EGO 共用这一动作质量清单，各自读取自己的相机与场景观测。训练特有的 EGO 可见性和 400 条椅子增强不扩展到验证/测试。

这些是保守质量规则，不证明动作在物理上完全正确；被标记的片段保留原文件，可供人工复核。

## 划分与历史评测

先校验完整源清单的元数据 SHA256、序列唯一性和物体家族跨 train/validation/test 的交集为空，再检查源数组及重建所需原始接触文件的身份。使用固定 G1 人体模板，先验证顶点子集计算与完整 SMPL-X 一致，并对每条序列核对重建关节和原导出关节，最大绝对坐标差不超过 2e-6 m。

本次有用户明确授权读取 GRAIL test 的源数据做质量检查。它不包括模型 test 评测、阈值调优、模型选择或将 test 数据加入训练；AMASS、EgoBody 和 TRUMANS 的 test 数组不在本次范围内。

输出根目录为 `runs/grail_heldout_quality_v1/`。`pilot/` 仅用于每划分每类动作一条的实现预检；`full/` 记录完整审计。每个输出包含封存依赖的 `JOB.json`、可恢复逐序列记录 `RECORDS.jsonl` 和状态 `STATUS.json`。完成后，`validation/` 与 `test/` 各有保留清单、剔除清单以及对应的可取片段起点范围；必须按这些范围使用，不能仅按保留序列全长抽样。

**原始划分、旧的 EGO 固定验证清单和已经发布的历史结果不改动。** 新质量清单是另一个显式版本；后续比较应让所有待比较模型同时使用这个版本，不能将筛选后结果直接替换旧结果。尚未接入训练/评测加载器时，不能声称这些帧已经被实际使用。

入口为 `python -m scenemi.data.grail_split_quality --output runs/grail_heldout_quality_v1/full --workers 4`，必须通过仓库资源包装器以 CPU 模式运行，使用 8 GiB 内存、4 核限制。原数据不复制，不生成大型人体顶点缓存，不使用 GPU。

## 已完成的全量结果

全量检查 4,196 条，独立验收通过；10 条预检样本与全量结果的事件及保留范围一致。逐序列重建关节与原导出关节的最大绝对坐标差为 4.77e-7 m。17,585 条源元数据身份核对通过，train/val/test 物体家族无交集。

| 划分 | 检查前帧 | 保留序列的总帧数 | 其中能被连续 128 帧采样覆盖的帧 |
| --- | ---: | ---: | ---: |
| val | 468,313 | 300,496 | 222,429 |
| test | 745,183 | 587,151 | 473,105 |

| 划分 | 规则标记及缓冲段 | 剩余不足 128 帧的片段 | 最终可用帧 |
| --- | ---: | ---: | ---: |
| val | 95,480 | 150,404 | 222,429 |
| test | 115,480 | 156,598 | 473,105 |

val 保留 1,096/1,663 条，test 保留 2,001/2,533 条。“规则标记及缓冲段”包括固定启发式规则标出的可疑段和前后缓冲；不代表这些帧都已人工确认错误。“剩余不足 128 帧”是在这些段之外，但因时间连续性不能被当前模型抽取的帧，不能通过删掉坏帧后拼接来使用。

证据：[完整状态](../runs/grail_heldout_quality_v1/full/STATUS.json)、[独立验收](../runs/grail_heldout_quality_v1/full/VALIDATION.json)、[简明帧数记录](../runs/data_inventory/GRAIL_HELDOUT_QUALITY.json)。新清单随后已接入下述 EGO 数据适配器和 EGO/EXO 共用选择入口，尚未启动新训练。历史 EGO 结果不回写；今后使用这个版本比较时，应让所有模型使用相同清单重新评测。

## 后续阶段的数据入口

当前选择合同为 [scene_data_current.json](../configs/scene_data_current.json)，记录源清单 SHA256 和两种视角 train/val 的逐来源预期帧数。新阶段的 EGO 使用 `scenemi.data.checked_scene_dataset.CheckedSceneDataset`；需要局部场景点时使用 `CheckedLocalSceneDataset`。接口与旧类相同，但验证只会读取保留序列及接受的起点范围，不会退回原始 GRAIL 全起点。训练仍采用原来的 7,011 条主选择加 400 条坐姿增强，不改随机连续 128 帧抽样。

EXO 使用同模块 `SceneSelection.records('exo', split)`，GRAIL 与 EGO 的动作序列和时间范围逐项一致，TRUMANS 读取完成后的移动相机 overlay；不把 EGO 的合成椅子条件复制进 EXO。这个接口提供经过核对的源索引，完整 EXO 观测到模型输入的适配仍须另行验收。

新阶段准备/训练前，先通过资源包装器运行 `python -m scenemi.data.checked_scene_dataset`。结果保存在 `runs/data_inventory/CURRENT_SELECTION_CHECK.json`；必须为 `passed` 且合同 SHA256 一致。加载时清单身份改变、数据帧数不符、错误划分或范围跨过剔除帧都会报错，不能自动回退到旧数据。三来源 test 准备未完整验收，训练/验证入口禁止读取 test。

旧 `SceneDataset` / `LocalSceneDataset` 及旧配置保留给历史结果复现和恢复；后续新阶段不得直接使用它们。新运行的依赖封存还须包含当前选择合同、选择文件和新适配器。历史结果的比较清单保持原样。
