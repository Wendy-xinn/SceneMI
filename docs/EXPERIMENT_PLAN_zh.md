## 训练前固定的验证选择

入口 `scenemi.local_training` 的 v3 协议每 1000 更新保存可恢复候选，并用固定小集评估所有这些候选（含零步基线）。小集包含全部 45 条 EgoBody、33 条 TRUMANS 验证录制各一个窗口，以及 GRAIL 五类动作各至多 20 个家族各一个窗口：按当前清单预计 176 个窗口。

结束后，用固定较大清单复核小集前三名和最终权重，去重后 3–4 个候选。该清单覆盖全部 16 个 EgoBody、33 个 TRUMANS、630 个 GRAIL 验证家族；每条原生录制取至多两个窗口，GRAIL 每家族至多两个窗口，优先不同录制，预计最多 1416 个窗口。短录制去重可能减少数量，实际值以 `runs/scene_ego128_local/VALIDATION_MANIFESTS.json` 为准。它覆盖全部家族，不是验证集每一帧的遍历。

两阶段使用同样的 128 帧、DDIM 20、seed 777，较大清单包含小集窗口。主指标为三数据集等权 MPJPE；EgoBody/TRUMANS 先按家族平均，GRAIL 先按家族、再将五类动作等权平均，避免 564 个楼梯家族淹没 23 个坐下家族。同步保留标准 PA-MPJPE、root/head 误差及其余现有指标；实际指标定义由 `scenemi.metrics` 固定。验证不使用合成补椅子，也不读取 test。

`selection/BEST.json` 在小集阶段明确 `provisional: true`；完成较大清单复核后才改为 `false`。每份候选权重都有步骤、SHA256、训练封印和逐窗结果，保留到选模复核，之后按依赖和哈希审计清理。这里的“最佳”仅指已评候选，不保证任意更新步骤的全局最优。计时会记录每窗耗时，开训后的 ETA 应包含验证与最终复核，不只用更新速度估算。

## 还需补的评估

- **场景依赖与可观测性**：同一权重关闭场景/局部条件/显式反馈作诊断；主结论还需匹配训练消融。针对“见椅子坐下、无椅子蹲下”单独检查场景敏感性；没有替代动作真值时，不能把反事实输出直接按原动作 MPJPE 评分。
- **接触与时序**：除了 MPJPE/标准 PA，检查足底支撑距离、滑动、可验证的穿透、坐下时座面关系、速度连续性；没有可靠完整几何时标记不可评，不能当零误差。
- **适配后遗忘**：EGO-only 场景和统一适配前后，分别保留 EGO 指标及固定 AMASS 回归结果；不能用混合平均掩盖 EGO 下降。
- **前置误差鲁棒性**：EXO 采用真实估计人体及其置信度，分别检查连续出画、深度/根轨迹漂移；理想观测上限与视频端到端结果分开报告。
- **补椅子增强**：真实相机可见场景是主设定；补完整椅子的受控实验单列，并比较有/无增强。人工加入完整椅子不能当成真实观测测试表现。
- **随机性**：候选排名接近时先复核固定验证家族上的成对差异和额外采样种子；最终主模型时间允许再补训练种子。单次训练不能证明 EXO 导致 EGO 负迁移。

这些评估大部分复用现有权重，不需要再增加一个训练分支。优先完成 EGO 主线、匹配消融和协议对齐，再扩展统一与全程 EXO-only；不承诺在单卡周日截止前完成所有完整重训。

## 已授权的无场景适配对照

本对照从 AMASS EGO-only 验证选定的 50k 初始化，适配 EgoBody / TRUMANS / GRAIL，仅 EGO、不使用 RICH。它不是再次从零预训练 AMASS。128 帧、batch 8、30k 更新、学习率、loss、数据家族采样、补椅子训练录制及其标签、seed 与局部分支相同。训练窗口和监督都相同，但相机之外的场景几何不进入模型；原生人体格式、相机内参和 TRAIN-only PV 共享外参继续可用，个体形状仍由允许观测预测。

为固定初始可训练共享权重和构造时的随机数消耗，先构造相同模型，再冻结未使用的场景模块并显式以 `use_scene=False` 运行。所有几何字段都不包含在推理 payload 中；全局 scene embedding、patch、逐帧几何、皮肤邻域及 root/rotation 反馈均不执行。保留相同的数据加载器以核对逐条身份，不把训练数据换成另一套范围。关闭几何后的唯一 denoiser pass 可节省计算，等更新预算不代表等墙钟预算。

验证逐条复用局部分支的 176 窗口快集及 1,416 窗口较大集。每 1k 更新保存候选、做快集验证，最后复评快集前三名加最终权重（去重后 3–4 个），各分支独立选模。快集最佳只是 provisional，不能拿一个分支快集结果与另一个分支最终大集结果做主比较。验收会核对初始全部权重、几何/标签污染不变性、原生 FK、体形梯度与逐位恢复，正式训练先重跑零步验证，并要求复现局部分支零场景门控的原始零步指标。

```bash
python -m experiments.offline_camera_retrain_v1.ops.resources run \
  --device cpu --memory-gib 10 --cpu-count 2 -- \
  python -u -m scenemi.benchmark train-control preflight --device cpu

python -m scenemi.runtime run --device cuda \
  --memory-gib 10 --cpu-count 2 --allocator-gib 6 -- \
  python -u -m scenemi.benchmark train-control preflight --device cuda

python -m scenemi.runtime run --device cuda \
  --memory-gib 10 --cpu-count 2 --allocator-gib 6 -- \
  python -u -m scenemi.benchmark train-control train --device cuda
```

入口复用已注册的 `scenemi.benchmark` 进程类别，现有训练的 `runtime.py`、数据、模型和训练源码封印不改。配置在 `configs/scene_ego128_noscene.yaml`，本地验收与运行记录在 `runs/scene_ego128_noscene/`。CPU/CUDA 验收和正式开训是分别记录的状态；配置存在不代表已经训练。并行会争用计算与 CPU，需用实际速度更新 ETA。

“完整场景版 vs 无场景版”测整体场景路径的收益；它还不能单独区分全局场景、局部条件和显式反馈。这些组件消融以后仍需同一父权重的匹配对照，不能用旧混训父权重分支代替。
