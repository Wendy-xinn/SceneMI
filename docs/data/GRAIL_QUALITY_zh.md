# GRAIL：导出完成与训练质量的区别

2026-10-22 对随机预览的 10 条完整序列进行了只读检查。每类均匀随机抽取 2 条，seed=2897015926；保留原始选择，没有替换不好看的案例。它们包括 train、validation 和 test，仅用于数据检查，不能据此选择模型或逐个删除测试难例。

17,585 条数据的预处理完成，表示身份、模板、时钟、文件与导出接口检查完成；元数据 `trainable=true` **不表示动作已经通过物理质量筛选**。源元数据也明确写有 `reconstruction_is_physics_validated=false`。

## 本次发现

| 案例 | 实际测量 | 含义 |
|---|---|---|
| 坐下样本 1 | EGO 151 帧均无高于地面 3 mm 的椅子表面像素；单独移除人体遮挡后仍为零 | 椅子存在，但该固定头部相机的视场没有提供椅子信息 |
| 坐下样本 2 | EGO 仅 13/151 帧看到椅子，最大 30/12,288 像素（0.244%） | 不能把完整源椅子网格当作模型已观测到的输入；窗口内可用信息仍需审核 |
| 楼梯 p2 样本 2 `terrain_stairs__stairs_2708__0001` | 第 198–222 帧（6.60–7.40 s）双脚最低皮肤点都高于各自竖直下方的最高表面 5 cm；第 205 帧左右为 17.16/17.10 cm | 存在明显支撑异常候选，不能仅解释为一只脚摆动 |
| 同一楼梯第 220 帧 | 右脚离最近三角面的距离为 10.86 cm；源估计接触概率为 0.934 | 偏差也不能单纯归因于竖直距离与最近表面距离不同；源接触概率不适合作为可靠接触真值直接使用 |

10 条预览都重新核对了原始 USD 的完整变换及 `obj_scale`，并直接用原始 24 Hz 人体参数在与 30 Hz 重合的时刻做 FK：每隔 4 个原始帧对应每隔 5 个输出帧，**所有重合时刻的最大顶点差为 0**。楼梯问题在这些不经过时间插值的时刻也存在。这支持“在当前已核验 G1 模板约定下，源重建本身就包含该偏差”，不能解释为查看器或 24→30 Hz 新引入的误差，也不能外推为所有源动作都不合格。

脚部采用左右踝/脚 LBS 权重之和大于 0.65 的皮肤区域，共 240/241 个顶点，逐点向下查询几何支撑。正常摆动脚不会仅因抬高而判作错误。负的竖直间隙是复核候选，并不等同于封闭网格的体积穿透；椅子下方的脚不使用这种地形判据。

## 进入场景训练前的要求

1. **动作与接触质量按任务筛查。** 对地形行走检查持续浮脚、支撑时穿透、滑脚；识别跳跃、摆动和接触切换，避免一律删除抬脚。坐下应检查臀部与座面的关系，不能套用地形足部规则。本轮没有实现完整坐下接触审核。
2. **场景输入是否足够按 EGO/EXO 分别判断。** EGO 没看见椅子的动作可用于不依赖该椅子观测的动作学习，但不能当作“已观测椅子可改善坐姿”的正例。EXO 应另查实际输入，不能随 EGO 一起删。只允许当前或此前真实观测到的场景，完整 GT 场景和包含未来帧的并集不能补入因果输入。
3. **以训练窗口为单位产生清单。** 对持续异常段应审核所有重叠的 128 帧窗口；必要时隔离窗口或屏蔽不可靠接触监督，而不是凭一帧外观删除整段序列。原始数据保留。
4. **先在训练集确定规则，再固定应用。** 当前 2 cm / 5 cm 只是描述性统计档位，不是已经确定的删除阈值。还需训练集分布与人工核验来确定持续时间、可见覆盖和动作类别例外；验证/测试集不根据模型效果或人工挑选好看程度修改。

上述随机预览审核只生成复核候选，没有改变虚拟相机或将人体吸附到台阶。用户随后要求只筛 EGO，第一步的全库场景可见性筛选见 [EGO 筛选说明](GRAIL_EGO_FILTER_zh.md)；追加的训练窗口接触检查见 [EGO 接触联合筛选](GRAIL_EGO_CONTACT_zh.md)。这不等于全库物理仿真验收。AMASS 阶段关闭场景，不依赖此处 GRAIL 场景质量。

## 复现与证据

新增工具位于 `scenemi/data/grail_quality.py`，复用既有源模板、读取校验与三角面查询，运行在受限 CPU 下：

```bash
python -m experiments.offline_camera_retrain_v1.ops.resources run \
  --device cpu --memory-gib 4 --cpu-count 2 -- \
  env CUDA_VISIBLE_DEVICES= python -m scenemi grail audit \
  --prepared runs/grail_preview/random_per_category_v1/PREPARED_CASES.json \
  --output runs/grail_preview/random_per_category_v1/quality_review
```

[紧凑审核证据](../validation/grail_preview_quality.json)包含全部 10 条序列、身份哈希、源对齐与质量统计。本地完整报告、逐帧数组、图和候选状态保存在 `runs/grail_preview/random_per_category_v1/quality_review/`。图同时展示脚—台阶侧视与逐帧间隙，源接触概率只作为辅助证据。

`tests/test_grail_quality.py` 的 3 个检查通过：左右接触通道与时间边界、摆动脚排除、最高支撑面/无交点及原始帧号映射。它们验证诊断实现，不表示全库物理质量已通过。
