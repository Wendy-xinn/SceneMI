# GRAIL EGO 场景可见性筛选

本文记录先完成的 EGO 场景可见性筛选。用户随后确认也需要筛查动作接触质量，对应的联合清单与进度见 [EGO 接触筛选](GRAIL_EGO_CONTACT_zh.md)。原始导出数据和相机保持不变，EXO 继续使用原始清单；不能把本文的可见性通过当作物理质量通过。

## 本次结果

全量扫描 17,585 条完成，使用 1 GiB / 2 CPU，约 150 秒；未使用 GPU。每条元数据身份、完整逐帧可见性计数与物体家族划分均通过检查。训练集结果如下，验证/测试仅输出覆盖审计：

| 类型 | 原训练序列 | 保留至少一个合格窗口的序列 | 保留的 128 帧窗口 |
|---|---:|---:|---:|
| 坐下 | 1,418 | 759 | 18,216 |
| 坡道 | 1,488 | 1,451 | 252,327 |
| 路沿 | 1,411 | 1,369 | 237,420 |
| 楼梯 p1 | 4,917 | 4,135 | 718,999 |
| 楼梯 p2 | 4,155 | 4,075 | 708,958 |
| 合计 | 13,389 | 11,789 | 1,935,920 |

原训练集共有 2,116,986 个步长为 1 的候选窗口，排除 181,066 个窗口；1,600 条序列没有合格窗口。窗口高度重叠，上述窗口数量不能当作独立动作数。因果历史保留了 196,237 个“当前窗口没有有效物体观察、此前已充分看过”的窗口。

随机预览里的两个坐下样本都排除于 EGO 场景训练：样本 1 完全没有非地面物体像素，样本 2 可见量过低。楼梯 p2 样本 2 可见性通过，**这不会消除其动作支撑异常**。

初版规则不随敏感性结果调整：较宽松/标准/较严格规则分别保留训练序列 12,177 / 11,789 / 10,947 条。[紧凑结果与验证证据](../validation/grail_ego_visibility.json)记录配置、输入输出哈希、各类别分布与已检查的预览案例。当前只生成数据清单，GRAIL 场景训练读取器尚未接入。

## 范围与规则

扫描全量已完成清单中的每条完整序列，核对清单中的元数据 SHA256、逐帧计数、30 Hz 时钟、虚拟相机参数与物体家族划分。可见量来自导出时保存的 **实际第一命中渲染统计**，不是完整源网格、人体真值、动作标签或模型误差。

交互物体可见像素使用元数据 `object_above_ground`：静态命中中排除 `abs(worldY)<=3mm` 的平面部分。该名称实际上表示“不与地面共面的静态表面”，不等价于逐物体语义分割，也不能证明看见的是座面或踏面。源场景只有交互物体和显式地面；与地面共面的物体部分也会被计为地面。

固定初版规则见 [`configs/grail_ego_visibility.json`](../../configs/grail_ego_visibility.json)：

- 单帧交互物体占 128×96 图像至少 1%，即至少 123 像素，才算有效观察。
- 同一录制从起点开始，累计有效观察至少 16 帧，其中至少一次连续 8 帧，才算获得足够的初步物体观察。
- 对每个 128 帧、步长为 1 的候选训练窗口，要求至少 16 帧已经获得上述观察。只保留符合条件的起始帧区间。

这是排除近乎没有交互物体观测的启发式门槛，不是已通过模型实验证明最优的参数。较宽松与较严格的档位同时计算敏感性，初版选择不依赖验证、测试效果。

## 因果历史与读取约定

沿用现有场景代码的因果静态记忆：录制开始后已看到的静态表面在转头后仍可保留。因此，某个窗口当前看不到物体，只要之前已充分观察，仍可能通过。之后才看到的物体不能使更早的窗口通过。

清单中的 `history_ready_frame` 表示观察条件首次满足的时刻；这是筛选统计，不是给模型补出完整物体。读取每个窗口时必须从同一录制先前的实际可见点构建历史，窗口内部逐帧更新，不能读取未来帧的离线并集。没有观察时仍需正确使用未知场景掩码。未来 GRAIL 训练读取器接入时应落实这一约定；仅载入窗口而丢掉录制历史，不满足当前筛选协议。

## 输出与使用边界

本地输出目录为 `runs/grail_ego_filter/`：

| 文件 | 用途 |
|---|---|
| `STATUS.json` | 完成状态、数量、配置与输入/输出身份哈希 |
| `TRAIN_DISTRIBUTION.json` | 训练集各类别的覆盖及门槛敏感性 |
| `DISTRIBUTION.json` | 全部分割的覆盖审计 |
| `visibility_statistics.jsonl` | 每条序列逐帧可见量、原划分、身份与各档结果 |
| `train/manifest.jsonl` | 至少有一个合格窗口的 EGO 训练序列；兼容既有紧凑清单格式 |
| `train/windows.jsonl` | 各序列可采样的 128 帧起始区间，端点包含在内、步长为 1 |
| `train/excluded.jsonl` | 没有合格窗口的训练序列及原因；保留原始数据 |
| `evaluation_coverage_audit.jsonl` | 验证/测试可见性诊断，不用于删掉基准评测样本 |

原始 train/validation/test 和物体家族归属不变。后续 EGO 场景训练应同时使用训练序列清单与窗口索引，不能只读取序列清单后任意抽取被剔除的窗口。EXO 和关闭场景的 AMASS 阶段不应用这一选择。

```bash
  --device cpu --memory-gib 1 --cpu-count 2 -- \
  env CUDA_VISIBLE_DEVICES= python -m scenemi grail ego-scan \
  --manifest /path/to/scenemi_recon30_v1/manifest.jsonl \
  --output runs/grail_ego_filter

python -m experiments.offline_camera_retrain_v1.ops.resources run \
  --device cpu --memory-gib 1 --cpu-count 2 -- \
  env CUDA_VISIBLE_DEVICES= python -m scenemi grail ego-filter \
  --output runs/grail_ego_filter
```
