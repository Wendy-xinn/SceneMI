## 修复分支

配置 `configs/scene_ego128_residual.yaml`，输出 `runs/scene_ego128_residual/`。从独立无场景适配 30k 的已选权重出发（SHA256 `33c102cc1dab381d1047b1a93056d1e1d38214504c33bb791087e4fd5ad0538d`），冻结原动作主干、相机编码器和个人体形预测器。原生人体适配、虚拟相机定义、TRAIN-only PV 标定继续沿用已核验版本。

只训练原有全局/patch/逐帧场景模块、预测皮肤局部条件和反馈模块。原主干保持 eval，避免冻结参数后仍受 dropout 影响。梯度可穿过主干，但只有场景参数更新。新增输出路径为零，必须逐位复现无场景基线才能通过验收。

每次 x0 预测将根平移修正径向限制在 8 cm，将原始旋转 6D 各分量增量平滑限制在 0.20，再正交化旋转并执行 FK。后者不是角度上限；前者不是最终采样相对原模型轨迹的上限，因为 DDIM 的中间状态会变化。另加软一致性损失：头部位置平方误差权重 2，根位置平方误差权重 1，参照同一步的冻结无场景预测。这不保证最终指标不退化。

沿用三数据集、EGO-only、128 帧、batch 8、家族采样、原生体形监督和 test 隔离。训练 8000 更新，学习率 1e-4，warmup 250，余弦衰减；每 250 更新覆盖一份 `last.pt`，每 1000 更新评原 176 窗口。最后在原 1416 窗口复评快集前三名加最终权重。零步完整快集必须复现无场景参考的逐窗结果。

CPU/CUDA 真实数据验收包括：零路径精确复现、冻结权重不变、真值体形污染不影响输出、场景梯度及有效修正、根修正边界、FK 一致、优化器/RNG 精确恢复、三个数据集真实 20 步 DDIM。以 `preflight/cpu.json` 和 `preflight/cuda.json` 为准，正式训练要求两份封印均匹配。配置存在不代表开训完成。

checkpoint 仅保存场景参数、优化器和全部 RNG，固定完整基线的 SHA256；必须保留基线才能恢复，不是独立完整模型。保存时原子替换。宕机恢复将未 checkpoint 的日志尾部另存为证据，避免样本身份重复计数。候选保留到选模审核，再按依赖规则清理。

## 执行与结论边界

复用已注册的入口：

```bash
python -m scenemi.runtime run --device cuda \
  --memory-gib 12 --cpu-count 2 --allocator-gib 8 -- \
  python -u -m scenemi.benchmark scene repair preflight

python -m scenemi.runtime run --device cuda \
  --memory-gib 12 --cpu-count 2 --allocator-gib 8 -- \
  python -u -m scenemi.benchmark scene repair train
```

CPU 验收将两个 `--device` 都设为 cpu；正式训练恢复追加 `--resume`。资源准入失败不启动，不干预其他用户。入口、实际导入依赖、配置、场景清单、人体资产和参考验证记录共同封印，运行期间不修改。

本实验回答“冻结已有相机动作能力后，再适配场景能否改善验证集”。它比原无场景 30k 多了适配预算，不能替代原 30k 对 30k 匹配消融。若有改善，还需额外训练预算匹配的对照、场景敏感性、家族成对差异和独立测试，才能支持论文主结论。当前未新增接触伪标签、BSTRO 或碰撞损失，不能把 MPJPE 改善直接称为接触正确。

`scenemi.comparison --run runs/scene_ego128_residual --watch` 是只读训练状态的 CPU 报告任务。选模结束后自动生成 `evaluation/REPORT_zh.md` 与 `COMPARISON.json`：逐条身份核验、独立复算原主指标，以及按数据集/动作分层的配对家族 bootstrap（5000 次，seed 20261025）。置信范围只描述当前选定权重在验证家族上的差异，不校正选模偏差，也不代表多训练种子或独立测试置信度。报告任务不能启动或重启训练；若训练失败或进程消失，会记录该状态。

## EGO-only 与后续统一训练的顺序

当前先核验 EGO-only 场景作用。EXO 对深度漂移、关节遮挡和支撑几何的收益需要单独实验，不能由 EGO 结果推断；加入 EXO 后的总体改善也不能归因于场景。统一版后续仍需自己的有/无场景对照，分别保留 EGO 与 EXO 指标。

冻结先验能限制遗忘，但共享场景模块仍可能发生任务间干扰。当前 EGO-only 相机/观测/体形分支被冻结，场景加载器也只产生 EGO 条件；不能仅修改混训比例就直接获得 EXO 能力。后续需先接通估计 3D 观测、连续缺失与深度/根轨迹误差协议，再训练 EXO 观测适配并保留 EGO 回放。

截至 2026-10-25 中午，训练已完成 8k；3k、5k 的 1416 窗口复评已完成，最终候选选择仍未结束。3k 候选 MPJPE 为 111.7758 mm，独立无场景基线为 113.7933 mm；改善 2.0174 mm，配对家族重采样 95% 范围 [-0.9168, 5.1939] mm。GRAIL 为 68.5541 对 68.3256 mm，未改善；这些是探索性验证点估计，不能据此声称场景稳定有效。完整暂定记录在 `docs/validation/scene_repair_3k_provisional_comparison.json`。

下一步证据包括额外训练预算匹配对照、正确/空置/错配场景的固定权重干预，以及在可靠可观测几何上的足底支撑、滑动、穿透与座面关系。保留原 MPJPE/PA/root/head 报告，不用后验挑选的有利类别替代总体结果。多次根据该验证集修改方案后，最终结论仍需独立测试。
