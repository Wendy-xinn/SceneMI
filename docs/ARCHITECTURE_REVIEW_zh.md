# EGO / EXO 架构复审与简化讨论

日期：2026-10-29（北京时间）。这是对当前代码、既有验证记录和原论文/官方实现的复审，供架构讨论使用；建议项尚未实现、训练或验证。本次只修改文档，不修改活动训练的模型、配置、数据、权重或进程。

## 1. 先明确结论和问题边界

当前 method 把逐次实验留下的工程设计组织成了多个命名模块，但没有相应证据说明这些模块都应成为最终方法。结构已实现、某次验证有改善、复杂结构优于简单结构、适用于真实前置输入，是四种不同结论。

需要重新确定的主线是：**同一个人体运动模型，接受不同来源、不同完整度的观测，在场景证据辅助下重建动作。** EGO 和 EXO 的区别主要在观测模型，不是两种相互竞争的人体运动规律。应先统一预测目标和条件语义，再判断哪些参数需要共享；不能先叠加保护措施，再用模块名称解释整个系统。

本次建议：把单次条件去噪作为最小比较起点；手工时间锚点、双前向输出差分、反复可靠性回填不再默认都是必要组件。边界条件已有局部有效证据，单独保留为待比较项。场景模块是否需要第二次人体提议，要另行判断。

## 2. 当前 EXO 的真实计算过程

主要代码：[joint_model.py](../scenemi/joint_model.py)、[exo_denoise.py](../scenemi/exo_denoise.py)、[exo_basis.py](../scenemi/exo_basis.py)、[temporal.py](../scenemi/geometry/temporal.py)。

当前过程不是“输入参考动作，直接预测修改量”，而是：

1. 将完整的初始估计 I 及其缺失填充值送入固定时间处理，生成 A。
2. A 来自六项提议：原始估计、宽度 3/5/9/17 的三角平滑、边界延拓。固定混合系数为 softmax([0,0,0,1,1,-1])。
3. 用 A 构造初始扩散状态；训练状态还根据可靠性混合干净动作和 A。
4. 每个扩散时刻，用同一主干计算无 EXO 注入的 reference。
5. 编码 I、当前扩散状态、可靠性、可用性、可见性，以及显式边界描述，注入同一主干，再计算 adapted。
6. 将 adapted-reference 乘 5，再经非线性限幅和可靠性门控，作用于 A。
7. DDIM 的下一状态继续与相同噪声等级的 A 按可靠性混合。
8. 返回最后一次干净动作预测；完全可靠的帧复制 I。

同一个可靠性信号因此同时影响：A、训练输入、输出幅度、采样状态、保持损失及完全可靠帧复制。各处有不同作用，但这种重复也可能过度约束修正，需要逐项证据。

### A 到底限制了什么

这里的 A 是**整段参考动作**，不是扩散时间索引，也不是某个关键帧时刻。当前 learned repair 确实严格限制在 A 附近。设 rho_p、rho_R 为已裁剪到 [0,1] 的可靠性，每次返回的干净动作满足：

```text
||预测根位置 - A 的根位置|| <= 0.5 * (1-rho_p) 米
每个关节相对 A 的局部旋转增量角 <= 1.2 * (1-rho_R) 弧度
```

例：rho_p=0.9 时，根修正最多 5 cm；rho_R=0.9 时，单关节局部旋转最多约 6.9°。这是上界，不是保证可以达到的修复量。A 相对 I 自身另有 0.25 m / 0.6 rad 上限。

八次迭代**不能**累加出 8×0.5 m 的修正，因为每次都重新围绕同一个 A 预测。当前 sampler 直接返回最后的 clean prediction，所以最后返回值也受上述相对 A 的限制。中间 noisy state 不具有同样的运动学意义。

这些约束不等于全身每个关节点位移上界：FK 会传播父关节旋转；也不等于相对真值的误差保证。对于根漂移大于可修正范围、可靠性偏高但估计错误、长时段动作转折等情况，正确解可能落在可表达范围之外。应先统计“目标相对 A 所需修正超过上限”的比例，以及实际输出的饱和比例，再解释失败原因。

**建议：** I 是已有参考，不必为了获得参考再增加多尺度混合 A。缺失填充可先使用一个明确的简单方案，掩码始终保留；时间平滑作为独立基线。可靠观测优先通过条件和软一致性约束保护。真实估计置信度不能直接当成绝对正确性的证明，只有明确的硬约束才应强制复制。

## 3. 两次前向有没有必要

当前差分可以抽象成：

```text
d = 5 * [F_theta(x_tau, c, injected_condition) - F_theta(x_tau, c, 0)]
预测 = 将有界 d 作用到 A
```

它的具体用途是：在确定性前向且零注入时，两项相同，学习修正为零，初始输出严格回到 A。这是可理解的初始化性质，但不证明必须付出两次完整主干计算。

对照方案可以直接输入参考、掩码与置信度，用一次条件主干预测 clean motion；也可以从这一次主干的隐藏特征直接读出相对 I 的平移和旋转修正。后者同样能通过零初始化读出层获得初始恒等映射。关键是修正必须利用共享主干特征，不能用一个旁路修正器承担全部 EXO 学习，再把它称为共享运动先验。

差分还有三项需要说明的代价：

- 在无场景 EXO 中，每个采样时刻两次完整主干计算；8 个时刻为 16 次。EGO 无场景 20 个时刻为 20 次。调用次数不等于实测速度，还需计入条件编码和 FK。
- 联合训练的共享梯度是两条路径的 Jacobian 之差，不是普通 clean-motion 预测梯度。在确定性、严格零注入时，共享参数的这部分梯度相消；注入非零后是否与 EGO 任务相容，需实测。
- 两个绝对输出的 6D 旋转坐标差，经补单位基、正交化再变成旋转增量，是一种人为读出参数化；它并不等于两个预测旋转的相对旋转。若声称几何上的旋转修正，应直接定义相对旋转或切空间增量。

**建议：** 双前向差分降为历史方案和待验证对照，不再先验地设为论文核心贡献。不能用直接关闭已训练模型的一条路径代替重新训练简单模型。

### 场景的两次前向是另一个问题

“先得到人体，再按人体位置查询场景”确有计算依赖，不能与 EXO 差分混为一谈。但查询位置也可以来自当前 noisy state 的合适估计、上一轮 clean prediction，或一个固定输入提议；这些方案是否稳定尚未验证。

当前场景 EXO 恰好把 reference 也用于皮肤查询，没有再调用第三次主干。可是场景查询的人体是未注入 EXO 条件的 reference proposal，最终修正却围绕 A；两个提议位置偏离时，查询到的几何未必对应真正需要修复的人体。这个偏离需要量化。

保留哪些实测点、自由射线与未知状态，是观测语义问题。即使删掉第二次主干，仍必须保留“未知不等于自由空间”的定义。

## 4. 现在究竟哪些共享、哪些分开

两个阶段需要分开看：

| 部分 | 四来源无场景 replay | 当前 scene_joint128_conditioning |
|---|---|---|
| 人体表示、FK、运动学资产 | 共同使用 | 共同使用 |
| 去噪主干 | 同一套参数；bottleneck、decoder、final_conv 等选定部分可训练 | 同一个 base 对象，全部冻结并保持 eval |
| 公共观测编码 | 共享调用；其中部分编码器可训练，不是所有编码器都解冻 | 冻结共享 |
| EGO 体形 | 根据观测预测；原生体形头可训练 | 冻结预测体形路径 |
| EXO 体形 | 已有 estimated rest；不是用 EGO 体形头替代它 | 最终 FK 用 estimated rest，但查询/条件另有不一致，见第 9 节 |
| EXO 普通条件、150D 边界条件、注入投影 | EXO 专用，可训练 | EXO 专用，继续训练 |
| EGO 场景适配器 | 没有启用 | 独立实例，可训练 |
| EXO 场景适配器 | 没有启用 | 另一个独立实例，可训练 |
| 场景适配器的权重 | 不适用 | 不共享；相同类不代表同一组权重 |
| 每次优化 | EGO/EXO 各半权重累计，同一次 AdamW 更新 | 同一个 optimizer 中有两组任务的专用参数；共享 base 不更新 |

来源：[native_joint_training.py](../scenemi/native_joint_training.py)、[replay/optimization.py](../scenemi/replay/optimization.py)、[scene_joint_replay.py](../scenemi/scene_joint_replay.py)。

当前场景阶段，两种任务没有经共同的可训练主干或场景参数交换知识。标准 AdamW 的一阶/二阶状态按参数分别保存，同处一个 optimizer 本身不构成知识共享。不过当前全局 gradient clipping 会按两条路径的总范数共同缩放梯度，因此仍存在数值上的耦合。

### “相同人体先验，为什么没有互相促进”

从建模上，更合理的出发点是同一个动作分布 p(X)，配合不同的观测似然 p(O|X,mode)，以及场景条件；条件模型学习的是不同观测下的后验。条件化后分布不同，并不需要两个互相矛盾的人体先验。

但参数共享不会自动产生正迁移。目前 EGO 是 full-noise、绝对 clean-motion 预测；EXO 是低噪声、锚点附近的差分修复，目标函数、噪声范围和梯度路径都不同。相同数据上的不同条件任务也可能出现梯度冲突。

已有日志直接记录了这个现象：replay step 256 的共享梯度余弦约 -0.356，step 512 约 +0.104。抽样诊断说明有同向也有反向梯度，不能证明训练全过程都在冲突，更不能把所有退化归因于 EXO。

完整验证中，AMASS EGO MPJPE 从 153.622 变为 162.569 mm，增加 8.948 mm，超过原定 +5 mm 门槛；step 2000 因此 `selection_eligible=false`。三数据集适配指标改善也真实存在，不能只保留一边。需要同数据/曝光预算的 EGO-only、EXO-only 与 joint 对照，才能识别任务冲突、来源迁移和训练预算的贡献。

## 7. 建议用于重新讨论的最小结构

```text
EGO：相机/头部轨迹 + 有效性 + 标定 -> EGO 观测编码 ─┐
                                                   ├-> 共享动作去噪主干 -> 动作/FK
EXO：初始人体 + 有效性 + 置信度 -> EXO 观测编码 ──────┘          ↑
                                              共用的场景关系编码（待验证）
```

先保留现有 U-Net 和明确的运动学表示，避免同时换主干、损失、采样和数据而无法归因。共享部分负责人体运动和时序结构；任务编码器负责两类观测各自的物理含义。不同人体格式保留必要的解码器，不为形式上的统一强行共用 SMPL/SMPL-X 参数。

建议默认先讨论统一 clean-motion 预测：

```text
X0_hat = FK_reconcile(F_theta(X_tau, tau, encoded_observations, scene_context), estimated_shape)
```

EXO 的 I 直接进入条件。已知参考并不要求再算一个无条件/reference 输出才能修正。输出减 I 就得到事后修正量；如需要结构上的残差预测，则用一次主干的特征直接读出 delta_p、delta_omega，再通过加法/旋转复合更新 I。这是读出选择，不再叠加成另一个必须同时使用的模块。长缺失段不能默认只能在一个错误填充值的固定小球内生成。

场景条件先明确共享的身体/世界坐标语义，再决定是否共享参数。两种模式对相同人体位置和几何关系应遵循相同几何规律；传感器原点、可见范围与观测可靠性由各自输入说明。缺少几何证据时模型退回动作/观测推断，而不是把未知当作空闲。

损失按作用解释：动作重建、有效观测一致性、时序质量、必要的体形监督。并非把现有约 20 项 EGO loss 改成四个大符号就完成简化；每个原子项必须列出监督量、单位、重复性和证据，删除项需真实对照。当前 EXO 固定 estimated rest，无法纠正估计骨长，因此应把体形残差带来的不可消除误差与姿态失败区分。

### 必须先定清的细节

| 层面 | 需要明确的选择 |
|---|---|
| 输入 | 是完整 pose-and-shape 估计，还是只有 3D joints？当前实现要求前者，不能把后者写成已支持 |
| 坐标 | 米制尺度、重力方向、人体与相机外参如何得到；EGO mount 与 EXO observer 各自作用 |
| 缺失 | 可用性、可见性和置信度含义不同；填充值不作为真实观测；多段、前缀/后缀、长缺失都要覆盖 |
| 输出 | 同一 clean-motion 目标，或有明确运动学定义的一次前向残差；避免任意 6D 输出相减冒充相对旋转 |
| 参数共享 | 逐个模块列出共享/专用、冻结/训练；同一个 Python 类或 optimizer 不算权重共享 |
| 可靠性 | 哪处条件化、哪处软约束、哪些确为硬约束；模拟 rho 与真实估计器分数如何对应 |
| 噪声 | 从标准 clean-motion 扩散起步；不同任务缩短采样需单独交代，不能只用“都是 diffusion”掩盖不同目标 |
| 场景 | 查询人体来自哪里，是否需要额外前向；surface/free/unknown 的证据来源；动态点按时刻对齐 |
| 训练 | 同样的源数据、曝光量、初始化和选模预算；50/50 样本或 loss 系数不保证梯度量级相同 |
| 推理 | 完整窗口离线设置；长序列拼接、延迟、主干调用数和端到端时间均需说明 |
| 实际前置 | 当前 EXO 主要由真值加扰动生成；真实前置要锁定 pose、shape、world root、visibility、confidence 来源 |

## 8. 最少的比较顺序，避免继续铺开实验

本节是讨论方案，不授权或启动新训练。

1. **先比较简单预测与当前修复。** 固定输入、数据、主干和训练曝光，比较一次条件 clean-motion 预测与当前锚点/双差分结构；保留 initial、简单插值/平滑、固定 A 的非学习基线。先回答复杂结构是否值得保留。
2. **再验证共享的价值。** 对选定的简洁结构比较 EGO-only、EXO-only、joint。分别报告两个任务，不用一个综合分数掩盖退化。区分每模式曝光匹配与总计算匹配，不能同时声称两者相同。
3. **最后加入场景。** 对同一动作模型和相同预算比较 scene 与 motion-only 适配器；检查正确/错配/空场景及有效几何区域。只有相应任务稳定受益，才写该任务的场景贡献。

每一步都可以得到“简单方案足够”“只保留边界编码”“共享未优于独立”“场景收益尚不足”的结论；这些是有效研究结论，不应自动触发再添一个模块。

边界编码的必要性可在第 1 步结构确定后单独回答；不必为了审查架构马上启动多个全预算分支。现有负结果和权重身份继续保留记录。

## 9. 当前场景实现还有独立于设计偏好的偏差

静态源码检查发现以下问题，尚未运行新的 CPU/CUDA 数值对照，不声称已量化其误差或确认它们造成现有性能问题：

- **多缺失段行为没有完整继承。** replay 构造 `NativeJointMotionPrior`，将 geometry 换成 `MultiGapTemporalBasis`；当前 `SceneBoundaryPrior` 继承的是 `JointMotionPrior`，会构造旧 `TemporalBasisExoPrior`。后者把所有缺失帧的首末位置当作一个区间处理。复制相同 state_dict 不能复制类的算法，因此多段缺失时零场景注入也不能据此宣称完整父模型一致。
- **EXO 条件的骨架来源变化。** 原 joint 路径直接用 `initial_rest` 构造 `body_condition`；当前场景 EXO 先调用 `base.conditions`，其中 rest 来自预测体形，随后只把另一个 shape 字典的 rest 改为 `initial_rest`。传给 `_core_pass` 的 conditioned 字典仍保留原先预测的 rest。
- **皮肤查询与修复骨架来源不一致。** `PredictedSkin` 使用 shape 中的 predicted_native_betas / predicted_template；场景 EXO 没有把这些替换为前置估计对应体形，只替换了 rest。最终 FK、查询皮肤与主干条件因此可能采用不同的体形假设。
- **两任务场景修正的位置不同。** EGO 查询当前动作提议并限制相对该提议的输出变化；EXO 查询 reference，却把 difference 作用到固定 A。两者使用同一个 RelationAdapter 类，不等于实现了同一修复机制。
- **配置和实际学习率不一致。** 当前 optimizer 只有一个参数组，update 只使用 lr_ego；配置 lr_exo=3e-5 未生效。实际两种任务都使用峰值 1e-4 的调度。

运行恢复、随机状态和资源问题已有独立记录：[SCENE_JOINT_TRAINING_DIAGNOSIS_zh.md](SCENE_JOINT_TRAINING_DIAGNOSIS_zh.md)。它们与架构必要性是两条证据链，不能用修复运行错误来代替证明模型设计有效。

## 10. runs 应该怎样独立

**实验状态应隔离，但每个 run 不必从随机权重开始。** 多个分支可以从同一个固定预训练模型出发；分阶段训练也可以明确继承上一阶段。需要区分：

| 情况 | 是否属于“相互保留信息” | 应有规则 |
|---|---|---|
| scratch | 不加载既有学习参数 | 固定种子、数据与初始化规则；不可暗中加载旧 adapter |
| 从固定父模型开始新阶段/分支 | 明确继承模型知识 | 记录父 checkpoint 身份；新建 optimizer 和随机流，除非声明继续训练 |
| 同 run resume | 恢复原训练状态 | 模型、optimizer、step、全部 RNG 和数据进度都属于本 run |
| 共享只读数据/场景预处理 | 重用输入，不是共享训练记忆 | 内容可核验、禁止训练覆盖；不能包含别的候选的未标注预测或 test 标签 |
| adapter-only checkpoint | 推理还依赖 base 权重 | 明确完整推理资产，不能当成独立模型文件 |
| 共享验证基线或结果缓存 | 复用计算 | 绑定模型、数据、窗口、噪声、指标实现身份；身份变化需重算 |

本次确认的当前依赖为：

```text
amass_joint128/scratch 的验证选定 100k
    -> scene_joint128_replay/parent.pt（硬链接固定）
    -> replay 的 step_002000.pt（完整模型状态，约 815 MB）
    -> scene_joint128_conditioning/training/last.pt（仅适配器，约 32 MB）
```

场景配置直接引用 replay 的候选路径和 SHA；场景 checkpoint 的 `parent_sha256` 不是父权重本体。删除 replay 父权重后，仅凭 32 MB 文件无法还原完整模型。这是显式的模型依赖，不是另一个 run 在后台向它注入隐藏记忆。

`pin_checkpoint` 使用 `os.link`。本次 stat 核对：scratch 的 selection/best.pt 与三个 replay pilot 的 parent.pt、正式 replay 的 parent.pt 共五个名字指向同一 inode；正式 replay 的 training/last.pt 与 candidates/step_002000.pt 也指向同一 inode。删除其中一个文件名不会释放其他名字仍引用的内容；原地写入则会影响同 inode 的所有名字，原子 replace 只替换相应目录项。因此固定权重应禁止原地改写。

`_anchor_payload`、`_proposal_cache` 是模型实例内部对当前输入的计算缓存；按这里的 Python 对象引用机制，它们不会自动跨独立进程传递训练信息。但它们要求缓存期间输入不被原地修改，不能把这种局部缓存与跨 run 的磁盘基座依赖混为一谈。

更合理的长期组织是：可复用的固定基座按内容身份放在模型资产位置，run 保存自己的输出及精确依赖清单；发布候选导出完整推理包，或完整列出并打包 base+adapter。历史 run 的来源记录可以保留，但不应仅为阅读历史状态就要求所有祖先 optimizer 和临时预测永远存在。清理时沿实际资产依赖检查，区分硬链接、独立副本、adapter 依赖和仅作溯源的记录。

本次没有删除或迁移任何资产，也没有据此把已知父模型关系改写成独立从头训练。

## 11. method 应如何重写

旧稿保留为 2026-10-28 实现快照，不能再直接当作已确定的投稿方法。先用中文回答四件事：输入有哪些、未知动作怎么预测、场景怎样改变推断、训练到底更新哪些参数。结构确定后再写英文。

主文建议只围绕问题定义、共享动作重建、场景条件、训练与推理展开。DDPM/DDIM、FK、mask、零初始化等既有工具说明来源和作用即可，不为每条工程规则另造一个缩写。卷积宽度、150D 特征逐项展开、每个阈值和每条损失的具体系数放在实现说明；影响方法可表达范围的硬约束不能藏进补充材料。

正文每个拟保留组件都必须能回答：“删掉它会失去什么？有哪个匹配对照支持？额外参数/主干调用/运行时间是多少？” 当前的 BOC、SRRD 等名字不能代替这三个答案。

投稿计划原先的日期目标保留为历史安排；主模型尚未定型时，不能把赶上某个实验日期作为继续沿用复杂结构的理由。
