噪声是明确声明的合成分布，尚未由真实前置估计器的误差统计标定。它是本轮适配训练设置，不能表述为已解决真实视频所有深度漂移。

## 取样与 checkpoint 选取

历史和本轮均先等概率选训练 family，再随机选原始/镜像，最后在该序列所有合法起点中随机选择完整 128 帧，附加随机 yaw。各次取样独立且有放回；**不优先选未见窗口，也不限制同一 batch 必须来自不同序列**。保留此分布是为了避免同时改变采样协议；日志逐样本记录 source、family、镜像、起点、yaw、遮挡及扰动参数，可据此审计覆盖和重复。重复起点不代表输入完全相同。

EXO 每 3k 更新同步评估**全部 337 条验证动作、2,222 个窗口**，两种固定条件各完整评一次，共 4,444 次窗口采样：`clean_masked` 为无位置噪声但有固定身体部位遮挡；`noisy_gap` 为固定带噪且含整帧缺失。两者不包含真实相机渲染遮挡。窗口起点为 stride 128 并加 end-aligned 完整尾窗；不镜像、yaw=0。每个 case 的数据 RNG 为 777+case_id，DDIM20、seed777；EXO 固定 batch8。

选择分数先在 family 内平均，再等权平均 family，最后等权平均两种条件的全局 MPJPE；越小越好，同分保留较早候选。分别保留根轨迹误差、根相对 MPJPE、PA-MPJPE、可见/缺失关节、各子语料结果。完整评估同步进行，训练暂停等待，因此不会因异步评估较慢而漏掉预定 3k/6k/9k/12k/15k 候选。`best` 指这些已完整评估的候选中最佳，不能保证未保存的任意一步都更差。

训练保留可恢复的 `training/last.pt`（每 500 更新原子写入）和 `selection/best.pt`。二者包含 EXO 参数、Adam 状态、数据/CPU/CUDA RNG、代码与数据合同、已提交日志长度；**必须同时保留已封存的原 EGO-only 55k 基座**，紧凑 checkpoint 不重复存一份约 980 MiB 的冻结权重。

EGO 不加入优化损失；每 500 更新用固定验证哨兵比较原路径和统一模型 EGO 输出，检查参数冻结。训练前后各做同一份完整 EGO 验证（batch4，与旧选择协议一致），核查所有汇总指标保持。该监测不读取 test，也不挤占 EGO/EXO 混训比例。

## 运行与进度

所有操作从仓库根目录执行，使用 `scenemi` 环境 Python。CPU/CUDA 都必须先通过真实 batch、精确恢复、EGO 保持、标签与缺失值隔离、DDIM/FK 验收。CUDA 由本轮授权扩展 [`exo_runtime.py`](../scenemi/exo_runtime.py) 启动；共享授权保存在本地 `SHARING_AUTHORIZATION.json` 并封存哈希。

```bash
python -m experiments.offline_camera_retrain_v1.ops.resources run --device cpu --memory-gib 10 --cpu-count 2 -- python -m scenemi.exo_training preflight --device cpu
python -m scenemi.exo_runtime run --device cuda --memory-gib 10 --cpu-count 2 --allocator-gib 5.5 -- python -m scenemi.exo_training preflight --device cuda
python -m scenemi.exo_runtime run --device cuda --memory-gib 10 --cpu-count 2 --allocator-gib 5.5 -- python -m scenemi.exo_training train --device cuda
# 故障恢复：同样的最后一条命令增加 --resume；恢复前仍做资源准入。
```

进度：`runs/amass_exo128/training/STATUS.json`；验证进度：`selection/STATUS.json`；选中的模型：`selection/BEST.json`；EGO 保护：`ego_monitor/preservation.jsonl`；完整协议与验证清单：`PROTOCOL.json`、`VALIDATION_CASES.jsonl`。完整验证期间 `completed_updates` 暂停增长是正常行为，`state` 会标明阶段，验证状态另报已完成窗口数。

验收曾发现历史 EGO 训练合同里的 CLI 源哈希与当前不同。逐字重建确认唯一差异是新加的三行 `exo-camera` 分发入口；其他原模型/数据/损失源码完全匹配。新入口不导入该 CLI，合同中 `initializer_cli_compatibility` 同时记录旧/新哈希及重建证明；没有修改旧合同，也没有跳过其他源文件校验。

## 起点与取窗

- 已完成的 AMASS EGO-only 55k 可以作为用户提出的固定初始化；50k 才是原完整验证选出的最佳候选。训练前锁定一个初始化及 SHA256，不能训练两个版本后按测试集挑选。
- 当前建议保留随机取窗，不仅因候选间隔为 1 帧而从零重训。已有 EGO-only 55k 覆盖全部 7,485 条动作、96.27% 的合格源帧；证据见 [覆盖审计](SAMPLING_COVERAGE_zh.md)。保留历史权重与源合同。
- 128 帧、30 Hz 不变。若另立固定 64 步长实验，必须独立记录全程起点规则、尾部完整窗口、随机种子和采样顺序，不能把旧权重续训称为从零的 64 步长实验。

## 分阶段训练建议

| 阶段 | 数据与模式 | 更新范围 | 核心验收 |
| --- | --- | --- | --- |
| AMASS EXO 观测适配 | AMASS train；EXO-only；场景关闭 | 冻结原去噪主干和 EGO 路径，仅训练新增 EXO 观测适配和独立体形预测参数 | EXO 补全/去噪/根轨迹验证；原 EGO 路径保持 |
| 三来源观测适配 | EgoBody、TRUMANS、GRAIL；覆盖 EGO/EXO；仍关闭场景 | 经单独验收的观测与原生人体接口，保留 EGO 对照 | 真实遮挡、世界坐标、人体格式与估计误差；排除 RICH |
| 场景分支 | 同一三来源、两种观测 | 优先冻结已验收先验和观测路径，训练场景分支 | 与同初始化无场景对照比较；分别报告 EGO/EXO、各来源 |

AMASS 的“EXO-only”指只用 EXO 样本更新新增适配参数，不是全参数只用 EXO 续训。冻结主干能否达到 EXO 所需能力尚需实验；若不足，需另行登记小范围解冻和 EGO 回放方案，不能预先保证效果。

最终统一场景分支建议训练两种观测；场景阶段 EGO-only 和 EXO-only 作为对照。共享场景参数仍可能发生任务干扰，须分别验收。若保持 EGO 原有曝光并额外加入 EXO，计算量会增加；微批次累计可以控制显存，但不能省掉新增计算。场景阶段单模态对照和全流程单模态训练必须分开命名。

## 体形输入

### 当前数据集实验：不依赖外部体形

- EGO 仍只有虚拟相机轨迹，体形从允许输入预测。
- EXO 目前输入数据集构造的带噪、带缺失的公共 22 关节轨迹、mask 和置信度，不额外输入个人真值 betas/rest。模型从这些允许观测估计体形，复用 AMASS 原生 SMPL-H 16 维解码，不需要先转换成 SMPL 10 维。
- 原 EGO 体形路径冻结；EXO 体形预测使用独立可训练参数，避免共享 readout 的更新改变 EGO。它是当前观测适配的一部分，不等于要求视频前置模型已经输出体形。
- 数据集中的真值体形仅用于构造干净人体、监督和评测标签。不能因它已经存在于数据集中，就当作真实推理时已知的 EXO 输入。若另外评测已知真值体形，必须命名为 oracle/known-shape 对照，不混入主结果。
- 当前 `public_observations` 没有外部体形字段，这与上述仅关节输入设定一致；新增 EXO 适配与体形路径仍须实现和验收，不能只改模式概率即开训。
- 三来源阶段仍须复用并核验已有 SMPL / SMPL-X / G1 原生解码接口。这是数据集人体格式兼容，不是某个视频前置模型的适配。

### 前置模型确定后：单独接入估计体形

- 前置模型未选定，因此现在不实施 VideoMimic 专用接口，也不等待它完成。
- 如果将来选定的前置模型提供体形，则把原生模型格式、估计系数、可用性与可靠性一起接入；仅关节输入路径继续作为缺省路径。增加该输入后须单独适配、验证，不能假定直接插入即可获得同样性能。
- 当前本地 VideoMimic/VIMO 是 SMPL male、10 维 betas；本轮 AMASS 是 SMPL-H neutral、16 维 betas。只有实际选择接入该类输出时，才需要验证原生解码到公共 22 关节及尺度，不能直接复制或补零后声称等价。其他前置模型按其实际格式处理。
- 若将来训练时模拟外部体形误差，应明确标记为合成估计，不当作实际前置模型输出。

## EXO 观测扰动

在完整干净动作监督之外，在线生成带噪观测：保留部分干净窗口，增加时间相关的姿态误差、根轨迹缓慢漂移、连续肢体缺失及整帧跟踪缺失。128 帧时钟不变，缺失观测与置信度必须一致，EGO 相机不人为断帧。

现有 AMASS 配置已支持结构化肢体缺失和 8–32 帧整帧缺失，位置噪声仍关闭。新的噪声强度、分布与课程必须在开训前固定；不等同于给每个关节独立添加白噪声。没有外部相机定义时，只能称世界坐标漂移，不把任意坐标轴宣称为相机深度轴。

无场景、缺少绝对锚点的观测不能保证辨识所有整体位移或深度偏差。前置体形能提供骨架尺度信息，也不表示它的全局根轨迹准确。

## 开训前必须通过

1. 初始化、train/val/test 成员、实际采样规则与训练预算封存；不根据 test 选模。
2. 当前仅关节输入及原生 SMPL-H 体形预测/解码通过核验；EXO 体形参数更新不改变冻结 EGO 路径。三来源阶段再核验其原生人体适配，不将未选定的前置模型列为当前准入条件。
3. 观测与标签严格分离，缺失位置/置信度一致，输入不含真值隐藏关节、旋转或个人体形。
4. 新增 EXO 路径在 EGO 模式关闭；模型保存/恢复后，同批次和固定 RNG 的下一次更新可复现。
5. CPU 和 CUDA 真实 batch 的前向、反向、采样与显存验收；使用项目资源准入，不影响当前导出或其他用户任务。
6. 固定完整验证清单和观测扰动种子，分别记录 EGO/EXO、可见/缺失关节、全局与根相对误差；提前明确 checkpoint 选择规则。

旧 AMASS EGO-only 55k 的日志时间跨度约 5.04 小时，旧 30k 三来源无场景训练末段报告约 0.485 更新/秒。它们是历史测量，不是新适配器的计时；新分支的剩余时间必须由验收实测重新估计。
