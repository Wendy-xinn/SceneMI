# 相机到头部、可信轨迹、帧率与真实 ego 视频前端

2026-10-12。依据当前 v2 代码及论文/官方代码核对；本轮只澄清接口与方案，没有训练、改模型、改采样频率或重导出缓存。前 3 项已有实现见 [IMPLEMENTATION_zh.md](IMPLEMENTATION_zh.md)。

## 1. 几何标定与相机编码是两件事

前端先输出相机位姿、时间戳与场景几何；接入层负责统一米制尺度、重力方向、坐标约定和时间。相机编码器将这些量及其语义编码成生成条件，它不是已验证的安装标定估计器。

对于固定在目标头上的相机，定义 `R_head_camera` 为相机坐标到头部局部坐标的旋转，`t_head_camera` 为头部局部坐标中的相机中心：

```text
R_camera = R_head @ R_head_camera
p_camera = p_head + R_head @ t_head_camera

R_head = R_camera @ R_head_camera.T
p_head = p_camera - R_head @ t_head_camera
```

必须先确认前端输出的是光学相机、设备还是 CPF 位姿，以及 pose 是 camera-to-world 还是 world-to-camera。设备到光学相机外参不能漏掉。不能只在世界坐标减去固定 xyz，也不能把光轴朝向当 pelvis 朝向。

**当前实际实现保留原始 head-mounted sensor 轨迹，并没有在输入端默认执行上述逆变换。** 相机与 anatomical 头关节通过类型区分；安装参数进入相机条件，观测损失将生成的头部位姿正向变换到相机再比较。已知安装时，两种表达在几何上可互换，但编码器本身没有“先反算头部”的步骤。相机分支和 sensor 槽来自同一流，同步扰动、缺失和 confidence，不能另接一份干净轨迹绕过扰动。

建议保留这种设备轨迹接口：已知且可靠的标定可在接入层产生带不确定性的 anatomical 头部估计；未知安装时保留 sensor 语义和安装先验，不能伪装为精确头部关节。当前 `mount_valid=0` 仅表明未标定，并跳过无法定义的安装一致性损失，没有验证任意未知设备的推理效果。

相机—目标关系用 self/other 描述，比“ego/exo 视频名称”准确：A 的头戴相机看 B，对 B 是 other；A 的相机追踪 A，自身才是 self。self 还不充分保证头部刚体安装，胸挂和手持相机要另标安装类型，不能套 head-camera 观察算子。当前 v2 受控 self 数据均采用头戴关系。

## 2. 观测适配以 confidence 为核心，保留必要语义

用户的理解成立：适配首先决定每帧每个部位“有没有观测、可信到什么程度”。最小条件为 `joint_id + position/rotation + 各自 availability/confidence + sensor/anatomical 类型`。位置可信不代表 rotation 也可信；只观测到的位置不能填入可信 GT 旋转。速度、加速度和角速度只在相邻所需观测均有效时计算，不跨缺失或镜头切换。

类型与部位 ID 不能被 confidence 替代：可信的相机中心仍不等于可信的 SMPL 头关节，可信腕部也不等于可信髋部。当前两个小型 sensor/anatomical MLP 用于表达这点，并不需要发展成两套完整的 ego/exo 网络。后续应比较 confidence/类型直接编码与这些小适配器，在匹配预算下判断收益。

实际代码边界：新增 typed 分支对特征乘 availability/confidence；轨迹一致性损失按置信度衰减。相机分支的 confidence 和旧共享轨迹 MLP 中的 confidence 主要是输入特征，**并未保证 confidence=0 时整个共享条件通路严格归零**。因此不能宣称整网已经实现统一的严格置信门控。若采用零置信度即无观测的接口，后续须同时核对旧通路、相机分支和投影 bias；训练仍暂停，不将此说明当成已完成代码修复。

目前 exo 的 confidence 来源是受控 first-hit 表面可见支持度；ego 的头/腕仍为理想轨迹加扰动。真实前端接入需另校准置信度与实际误差的关系。生成或补全出来的身体/手，不能仅因为轨迹平滑就记作 confidence=1 的实测关节。

## 3. 20Hz 的来源与 30Hz 的取舍

20Hz 是现有动作预处理、完整可见场景缓存、55k/3k 模型及评估的共同协议；v2 为了可比较而继承它，不是论文或 ego/exo 统一任务的硬要求。当前原生动作从 30Hz 直接重采样到 20Hz，位置插值、旋转 SLERP，源帧查询为 `source_start + 1.5 * index`，不是简单隔帧丢弃。当前原生版本不能和早期 RICH 的 5→20Hz 代理数据混称。

|设置|按帧数/频率计的窗口时长|意义|
|---|---|---|
|128 帧 @20Hz|6.4s|当前配置|
|128 帧 @30Hz|约4.27s|上下文更短；不是只提高播放流畅度|
|192 帧 @30Hz|6.4s|保持近似相同时间上下文，时间采样数增加50%|

严格的首末样本时间跨度是 `(T-1)/fps`。30Hz 有利于保留更细的快速转头/手部运动，并减少原始 30Hz 数据的动作插值；20Hz 是否丢失影响任务的细节，需要匹配时间上下文的对照，当前没有实验结论证明哪种更好。

若另做 30Hz 版本，需统一修改：

- 从原始动作、相机、物体和 contact 时间戳重新生成同时间轴的数据；视角可见性/动态点云重新计算，不能把 20Hz 可见点简单插值冒充 30Hz 观测。
- 将当前 `FPS=20` 和固定时间查询改为显式 fps 或 dt；位置 m/s、加速度 m/s²、角速度 rad/s 的计算与评估同步改变。
- 审计旧 base objective 中按帧差分的项、脚滑每帧阈值、短缺失帧数和时间滤波。物理导数的归一化尺度可保留其物理定义，权重仍需重新核查。若某项确为未乘 fps 的平方差分误差，维持相同连续时间权重时一阶系数随 fps²、二阶系数随 fps⁴ 换算；不能将此换算套到所有 loss。
- 保持相近秒数的窗口，重新标定初始监督梯度与训练预算，保留独立版本记录。现有 U-Net 没有通用 dt 条件，不能直接把 55k 模型当成原生 30Hz 模型。

当前保持 20Hz；输出插值至 30fps 可用于回放，但不算原生 30Hz 生成能力。网络视频按真实时间戳接入，帧率可能是 25/29.97/30/60 或可变，不能仅按帧号假设 30Hz。

## 4. 专门针对拍摄者不入镜的 ego 方法

下表只引用论文及作者官方来源，核对时间为 2026-10-12。它们并非都能一键替代同一个前端。

|方法|输入与能提供的信息|接入时的主要限制|
|---|---|---|
|[EgoEgo，CVPR 2023](https://lijiaman.github.io/projects/egoego/)|ego RGB → SLAM/学习得到头部运动 → diffusion 生成拍摄者完整动作|符合“头部运动作为中间接口”；使用固定平均人体形状，不能解决真实个体体型|
|[EgoAllo，CVPR 2025](https://arxiv.org/html/2410.03665v3)|米制设备/CPF SLAM 位姿，结合图像手部观测 → 拍摄者身体、身高/shape、手部|需要先有可靠米制 SLAM 和地面参考；不是单目 RGB 的完整相机/点云恢复器。CPF 到 SMPL 头关节偏移依赖 shape|
|[UniEgoMotion，ICCV 2025](https://chaitanya100100.github.io/UniEgoMotion/Patel2025UniEgoMotion.pdf)|重建模式输入 ego 视频与设备 inertial SLAM；统一重建、预测、生成|“统一”指这些 ego 任务，不是 ego/exo 统一，也不能把所需 SLAM 轨迹省掉|
|[ReViV，ECCV 2026](https://arxiv.org/html/2607.17790v3)|单目 ego RGB 联合预测 body/hand/gaze、相机与 depth；最接近用户描述的组合|人体输出主要为关节轨迹，不等于恢复准确个体 SMPL shape；论文相对 depth 需地面/VIPE 线索做尺度对齐|
|[Map-Mono-Ego，2026](https://arxiv.org/abs/2605.20889)|单目 ego 视频与预扫描点云，用已知地图约束全局人体定位|适合已有米制地图的受控条件；需要预扫描地图，不能据此声称任意网络视频无地图也可恢复|

[ReViV 官方代码](https://github.com/lvsean/reviv4d)已提供权重和 demo。需要区分论文与发布 checkpoint：官方 README 列出 relative-depth 与 metric-depth 两套权重；metric 输出仍是估计量，需要验证误差。demo 默认处理一个约 2 秒窗口，body 为 `[60,21,3]`、camera 为 `[60,9]`，输出 30fps；与 SceneMI 的 22 个 native 关节、6.4 秒窗口和设备坐标之间均需明确映射。长视频拼接及全局坐标连续性没有由该短 demo 自动得到。它给出的隐藏身体是模型推断，不应作为本生成器的高置信实测输入。

[Human3R](https://fanegg.github.io/Human3R/)可联合估计场景、相机及画面中被检测到的人体，因此适合 exo 可见目标的初步前端。依据其检测到的 head token 构造人体查询这一机制，拍摄者完全不入镜时，不能期待它直接检测并恢复拍摄者身体；它的场景/相机输出是否能满足 ego 的误差和尺度要求需要另测。这是对其适用边界的推断，而非声称代码禁止 ego 图像。

## 5. 当前建议与尚未完成的验证

数据集阶段先完成现有 self/other 条件与输入对齐验收：真实 PV 与合成安装分别标定；保留共享动作头；场景结构和训练暂停状态继续保持。已知 native body 是当前提供的标定条件，未知视频的个体身高/体型估计尚未接入。

真实网络视频阶段可单独评估 ReViV 的相机/depth，或以 EgoEgo 式头部前端作对照；已有可靠设备 SLAM 时参考 EgoAllo 的设备/CPF 表达与身高估计。**这是接入候选方案，不是已经运行的实验或性能结论。** 只将可靠相机轨迹、实际可见手/关节及经过验证的场景作为生成条件；先验证其时间、米制尺度、重力和相互对齐，再测最终动作。

拍摄者看不到并不妨碍通过背景估计相机运动，但使真实完整身体和体型无法由图像唯一确定；地面相对相机高度还能随蹲坐、楼梯而变化。体型阶段宜先估计/校准整段一致的身高或少量骨长参数，保留默认形状先验的不确定性，再考虑完整 beta，不能逐帧改变身形来吸收 SLAM 漂移或关节误差。EgoAllo 的实验也说明身高比体重更能从头部运动得到约束。

前端最先登记的实际误差包括相机平移/旋转漂移、尺度误差、地面法向/高度、快转头造成的模糊、可见手轨迹误差及镜头切换。输入速度和加速度应在完成坐标/时间统一后计算；差分会放大前端抖动，可信度与适度的时间滤波需一起验收。不能把前端噪声以强监督再放大到生成动作，也不能以平均平滑取代真实快速转向。
