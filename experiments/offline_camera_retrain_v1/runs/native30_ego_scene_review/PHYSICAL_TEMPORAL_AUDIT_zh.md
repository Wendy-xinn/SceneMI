# 物理修正与时间稳定性：冻结输出 CPU 审计

结论：当前验证抽样支持先关闭显式物理 solver，保留 learned scene 路径。局部加权总能量下降确实发生，但这不等价于最终足部速度、加速度或整段动作质量改善。本文没有修改物理代码、模型或推理结果。

范围为 12 个独立录制（RICH/TRUMANS/EgoBody 各 4），每个录制各 clean/noisy，24 组 `learned_only` / `full` 配对；共复用 48 个既存预测。不是完整验证集或 test。所有配对的输入、reference、GT 与 seed 一致，NPZ SHA 和冻结源码与 PLAN 匹配。CPU 重新 FK 后复算 World/速度/加速度/足速/足高指标，与保存行完全一致；没有初始化 CUDA。

**差分定义必须保留：以下 `full − learned_only` 是两臂 DDIM20 后最终整段输出之差，包含后续扩散状态、learned proposal、接触预测及场景重查询的轨迹分化。它不是某一次 `guide_motion` 的原始修正量。**

## 最终质量变化

所有列均为越低越好；足速仅统计 GT 足关节 10/11 的三维速度 <0.2m/s 的帧，报告其中的水平速度。加速度为全 22 关节相对 GT 的二阶差分误差。宏平均对三个数据集等权；clean/noisy 共享录制。

| 范围 | 最终根平移差均值 mm | 最终足位置差均值 mm | 扣除根平移后足位置差均值 mm | 足速度向量之差均值 m/s |

扣除根平移后差异仍明显，说明最终动作变化还包含根旋转及其他关节姿态；这些量的范数不能相加为贡献比例。JSON 另存局部旋转差、旋转修正的逐帧角变化、各窗口最大足部加速度差附近帧。

一个直接可核查的例子：RICH case0 / LectureHall_003_wipingchairs1 / start256 / clean，最终 `full−learned_only` 右脚 x 在窗口帧 112–116 依次为 **−25.30、+20.83、−25.14、+21.00、−23.92mm**；同时 root x 为 **−5.08、+4.35、−4.84、+4.30、−4.56mm**。最终差分确实出现逐帧交替，不能只凭根位移很小判断时间质量安全。此例不是单次 solver raw delta，也不能仅由这些差分确定是哪一步或哪种门控造成。

30Hz 会放大这种变化：理想化的 ±1mm 逐帧交替位置差，即对应 0.06m/s 的速度差和 3.6m/s² 的加速度差。小位置修正与明显时间副作用可以同时出现。

## 代码可以证明的边界

- 保存诊断共有 480 次 guide 调用，其中 208 次有非零初始能量，194 次接受更新、合计 328 次迭代；其余 272 次零能量主要为跳过路径，不能当作已优化到零。所有非零能量调用的 after≤before。不同 DDIM 调用各自重建 evidence，不能把这些能量视作一条连续下降的统一轨迹目标。
- `native30_physical_guidance.py:88–106` 的目标是接触距离、浅层局部平面、slip、观测位置、位移 prior 和修正量一阶差分的加权和；没有最终动作加速度、关节角速度或角加速度约束。总和下降允许某个子项变差，代码也未要求各帧能量都下降。
- `:97–100` 的 slip 只在相邻帧选中同一 anchor、接触权重同时有效、表面速度有效且 owner 相同时生效；允许 0.2m/s 死区，总权重仅 0.02。它衡量预测接触的 skin anchor 对观测表面的相对速度，不等于评估中 GT 低速帧的足关节水平速度。
- `:102–104` 的 temporal 惩罚是 Cartesian 修正量的一阶差分，不是最终动作的二阶差分。在第一迭代的零修正处，这个项和 prior 的梯度为零；候选接受时仍会计入它们的非零惩罚。
- `:126–145` 每帧根平移、每帧/关节旋转分别计算并裁剪梯度；**backtracking 的 fraction 则对整窗统一**。接受门控要求总能量下降、可信观测位置误差不增超过2mm、当前 guide 相对其 base 的 root 最大变化≤20mm。已存单次 guide 最大 root 变化 19.913mm；最终两臂 root 差最大 21.668mm 是整条采样轨迹差，不受这一个局部20mm门槛直接保证。
- `:120–123` 的 evidence 在一次 guide 内固定，但在下一次 DDIM 调用重建。最近表面、每区域最近 anchor、接触阈值、邻域/法向有效性会随帧或采样状态改变。`native30_refinement.py:207–214` 又对候选运行观测 proximal / IK；头部位置保护也不保证脚部时间稳定。

## 机制推测与目前不能证明的事

最近点/anchor 切换、接触门控、逐帧裁剪、有限两次迭代及后续 DDIM 重查询，均可能让局部位置修正带来高频变化；现有输出足以证明最终差分存在时间交替，却没有保存每帧 solver evidence、分项能量、raw angle update 或接受 fraction，因此不能归因到某一种机制或声称已经定位唯一 bug。也不能据此判定无场景更好：learned_only 已保留学习到的场景作用。

当前取舍只针对这份小型 EGO 验证面板：后续公平短训两臂均 physics OFF，优先比较 learned scene 与新增 attention；物理 solver 如需改进，应另设独立且有时间质量门槛的实验。当前不做该改动。
