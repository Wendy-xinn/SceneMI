# 实质改善候选：实际身体状态 + 相对运动 + 连续软约束修正

已获得短期重建指标改善的推理候选；用户可视化指出明显脚滑、头部姿态及沙发穿透问题，当前尚未通过运动与场景几何验收。冻结配置后，在另一批48窗口、16身体序列、12录制上确认了世界/PA误差与身体朝向的改善，脚滑增长约1.6%，没有上一版逐帧IK的高频抖动。它是现有模型之上的状态相对修正，尚不是重新训练出的模型，也没有证明全部反向转身或物理跟踪问题已经解决。

## 方案如何工作

1. 保留同一模型、已知未来头部与逐时刻场景、以及前16帧可信实际身体历史，先用原前缀DDIM20生成。
2. 根位置从实际最后状态和最近三步速度开始，保留模型未来世界位移；根朝向从实际状态继承模型的相对旋转增量。这里不旋转整条未来世界路径，避免把头部目标和场景路线一起转偏。
3. 其他关节通过原生SO(3)过渡接入实际姿态，32帧后回到模型的局部姿态先验。脚部目标从实际脚状态/速度开始，保留模型未来脚的位移与相位，不用速度阈值猜接触后冻结脚。
4. 下肢拟合这些脚步目标；上身独立拟合带可用性和置信度的头部位置/旋转，头部置信度以平方进入软损失。根节点不由头部IK移动，膝关节新增IK修正限于局部X轴。
5. 修正自由度是每四帧一个控制点的自然三次样条，不是每帧自由优化。全部动作由native SMPL/SMPL-X共享22关节FK解码，保持骨长。

首步根位置、第一姿态的衔接部分由结构直接施加，不能把它们的误差下降当作独立模型学习证据。更有价值的证据是未来世界/PA误差、朝向、脚滑、头部噪声稳健性及角运动统计一起改善。

## 仍然没有解决的部分

- 相对根朝向显著减小绝对朝向偏差，但保留模型本身的转身增量。确认集短期有意义反向转身率1.92%→1.92%，转向幅度不足35.26%→35.26%。因此没有宣称消除了左/右反转；完整未来clean反向率0→0仅是这批筛选子集结果。
- 初始角速度没有作为严格连续约束，首帧局部姿态基本承接最后状态；未来需要检查实际控制器的速度/加速度边界。
- 脚部目标是模型位移加实际起点，不是scene SDF、mesh接触或动力学求解。没有验收自碰撞、全mesh穿透、碰撞避障或仿真器跟踪。
- 单样本、历史16+未来112帧、DDIM20+60次修正的接口测试约1.916秒。当前不满足20Hz实时；仿真器可暂停的规划试验可以使用，实时部署需要缩短范围、热启动或蒸馏。

## 为什么前面几轮没有稳定解决

目前证据表明，原模型即使收到实际身体历史，绝对姿态输出也没有保证衔接；强行整体对齐头部会移动脚部。只匹配扩散前缀或加入开头损失，没有显著修复采样后的状态连接。这次把已执行状态写进位置/旋转/脚步目标结构，并让头部优化作用于上身，取得了可复现收益。

本轮还排除了几条方案：整体刚性朝向连路径一起旋转会损害长时世界轨迹；仅姿态过渡会增加脚滑；按速度猜接触并锁脚会引入角运动尖峰；逐帧自由IK虽然降低MPJPE，但确认集腿部角加速度p95达到7.144°/帧²、GT为3.199，不能采用。这个旧holdout已经暴露问题，之后使用另一批录制确认样条版本，未把旧holdout继续当作未见测试。

## 实际接口与可视化

`state_relative_planner.generate_state_relative_plan` 只传入头部、场景、native身体参数及实际历史。它删除未来body/contact GT字段和非头部未来轨迹；返回完整未来动作及建议执行的短块，默认4帧=0.2秒。下一次必须使用实际执行/跟踪状态，而不是旧规划未执行部分。身体状态若不可信，接口拒绝作为精确锚点；真实视频头部仍使用软条件。端到端接口与固定例子的直接评估一致，骨架/置信度/GT独立性检查通过。

Viser：`http://127.0.0.1:8780`，850/906固定历史失败例子。蓝色GT mesh、红色同模型原前缀生成、绿色新方案，可叠加/单独查看；默认播放预测16–47帧，可切换完整未来16–127；含相机、当前可见点和对应时刻动态物体。静态记忆按当前帧首次观测时间过滤，动态物体不会显示历史轨迹几何。保存的是小型motion和场景显示数据，mesh运行时解码。

850短期：世界MPJPE6.740→5.861cm、骨盆朝向12.613→4.153°、脚滑0.658→0.671。906：9.132→5.752cm、19.438→9.179°、脚滑0.611→0.590。它们只是示例，结论来自开发/确认集。已检查906的0/0.6/1.4秒native mesh静帧，没有看到明显的原先腿部扭曲；动画和物理碰撞仍需要验收。

## 场景与数据日志

保留之前通过审核的native20场景/静态记忆/当前动态处理，没有重建缓存、改变数据频率或把动态历史加入地图。已知未来场景在本轮仍是录制条件，真实在线部署需要提供已知地图和逐时刻预测。

额外发现 `dynamic_object_points` 在缓存读取路径中继承了未被模型使用的legacy点采样计数。固定850/906重读时计数分别98→100、1203→1191，其他身份、源帧、bundle、body参数完全一致；这不是当前缓存BPS动态点变化。为保持冻结训练合同，本轮没有修改data.py；demo单独记录实际visible owner1..99计数和历史计数差异。后续数据合同版本应修正这个日志字段，不能用它证明动态几何数量。

## 存储与下一步

本轮没有新训练、没有新增checkpoint。旧head-only baseline500已退役，剥离optimizer并逐张量核对模型一致，回收约0.962GB；保留模型/RNG/配置。官方55k、当前delta_history500控制/起点和有用joint_all1000完整保留。native数据依赖不动，薄动作演示数组留本地。

建议先验收Viser中的朝向和步态，再接实际仿真器短块执行/状态反馈。确认闭环有效后，把状态相对输出和连续修正融入训练或蒸馏，减少优化耗时。当前结果不支持直接继续旧损失配置的55k，也不支持声称反向转身已全部解决。

## 滑动窗口说明与失败候选清理

本轮滚动就是16帧身体历史＋未来生成，执行8帧后窗口前移8帧。128是每次调用的总窗：第1次历史0–15、未来16–127、执行16–23；第2次历史8–23、未来24–135、执行24–31。后续历史由各自已执行生成块更新，未刷新GT。20次执行组成160帧=8秒，并非把一段128帧循环播放。

原演示是128帧总窗；训练允许64/128/192帧。本轮单次参考用192总窗，从其中评分同样160未来帧；288仅是提取连续观测/末端lookahead的容器，不是网络输入。原500步历史模型没有充分学习反复执行反馈的跨块状态/脚步相位，已有matched/boundary500步也失败；滑窗方向值得保留，但需要针对协议微调/输出约束验证，不必从零重训55k。

按用户要求删除4份长滚动与2份场景修正失败motion数组，共17,025,655字节，保留指标/代码，未删正式权重或源数据。原850.npz、906.npz及manifest保留。8780恢复850/906，默认完整未来5.6秒、蓝GT与红参考，旧其他对照可手动开启。新viewer巨大紫色形状来自轨迹线宽2按world单位解释；已显式改为screen像素，原viewer继续使用细线相机线框。清理见[记录](../long_history_rollout_oct10/cleanup.json)。
