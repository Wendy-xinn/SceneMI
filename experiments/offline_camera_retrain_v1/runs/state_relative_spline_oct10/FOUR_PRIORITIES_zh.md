# 四项工作的统一状态和后续验收（2026-10-10）

本页作为后续尝试的入口，不把不同权重、不同输入、短期裁剪、完整生成和滚动执行混在一起。最新场景候选未通过，绿色不能称为比红色好的方案。红色也不是原55k：它是joint_all1000→delta_history500，加可信历史前缀采样。原55k必须另列。

历史模型已经使用64/128/192帧变长训练；64帧也包含16帧历史。因此“没有短窗口训练”不准确。缺少的是训练、推理、实际执行块和历史更新统一的滚动协议。当前网络仍输出每帧绝对状态，head delta是输入特征，不是身体增量输出。

22区域由原生顶点主LBS关节聚合，不是22个关节中心的接触真值，也不是全顶点预测。无标签帧/数据集不当负例。contact head读取生成motion和相机局部BPS；BCE可反传生成网络，但接触标签本身不等于网格避碰或锁脚。当前delta_history的repair_objective=baseline，保留BCE，没有沿用先前coupled_contact的关节几何代理。最新场景修正使用生成速度与静态表面猜软接触，并没有使用contact_logits，这两件事必须区分。

正式55k报告的接触F1来自4个RICH固定窗口，不能当成全val接触性能。既有coupled_contact实验仅把总体脚滑0.648降至0.640，穿透代理未改善，不算接触问题已解决。

## 身体历史是否保留、是否滚动生成

保留作为必要接口：后续tracker返回的实际状态、近期线速度/角速度与已执行接触状态必须能参与重规划。历史是避免每次重新猜当前动作的依据，不是保证历史支路训练有效的证明。实际sim状态可信时可以固定过去；视频估计身体历史不可信时应走软条件，不能硬锁。

建议首先在冻结同一红色模型下，比较单次生成与滚动生成。先不同时修改权重、输出表示、场景修正和接触损失。滚动规划总窗64帧：16帧历史0.8秒＋48帧未来2.4秒，每次执行8帧0.4秒。128帧规划总窗作为同执行长度对照。当前只做过4次重规划/1.6秒，而且第一次128帧、随后64帧；这不能代替固定窗口的长时间滚动检验。

目标看至少8秒连续执行动作，包括转身、行走、坐下、接触切换，而非重复刷新GT过去。首次GT身体只作为初始化诊断，之后运动学代理由各自真正执行的生成块更新；仿真阶段改为tracker实际状态。GT身体只评分，已知未来头部/静态地图/有来源的动态预测允许输入，不能偷偷加入未来body/contact标签。动态未来未知时不保持旧位置形成ghost；场景记忆也不能每个短窗清空。场景累计需固定静态观测截止时刻，动态逐时刻处理。当前接口速度未达实时要求，先做离线验证。

## 固定对照，按证据推进

1. **滚动协议对照**：原55k统一物理头部条件作为外部参考；同一红色模型单次/64帧滚动/128帧滚动，同过去初始化、未来条件和配对噪声规则。先证明长段步态、衔接和方向不会因滚动恶化。不要把不同窗口带来的扩散噪声形状差异当成逐元素完全相同采样。
2. **接触审计**：冻结红色模型，先在RICH有效标签上评估未来预测的22区域接触，分区域precision/recall/F1、标签覆盖和置信度，检查脚掌、臀部、手等接触切换。不是只在GT motion上测contact head。检查native足底与源地板的厘米级冲突，再确定可用mesh接触监督；没有标签的数据不伪造真值。
3. **场景修正**：以上固定后，对同一生成分别添加场景几何、几何＋软接触。稀疏观察和接触未知时回退原生成；不能在无几何时仍改朝向/头部。可信支撑脚切向滑动、起始身体速度、头部软观测误差设预算，在预算内减穿透。动态接触用物体相对速度，不能静态锁定。
4. 只有训练损失确实缺少所需约束且冻结对照支持时，才做一组匹配预算短训。一次只改历史/滚动训练或mesh接触监督之一。通过后再考虑长训及状态增量输出，而非继续混合调头部权重。

## 后续统一验收

这是后续约定，不是已跑完的新结果。展示连续拼接的执行块，分别评分完整执行段、跨重规划边界和末段漂移；完整计划仅作辅助，不能用每次规划开头裁剪替代执行段。按录制聚合，分三个数据集/四角色，固定身份、多个种子；先在已经暴露的开发集筛查，再用尚未调参的录制确认。

主要指标包括世界MPJPE/PA-MPJPE、方向反转与少转、实际转角、支撑期脚滑、脚部速度/加速度、悬浮/穿透、边界位置和速度跳变。完整mesh和动态碰撞单独报告，局部代理不冒充它。接触移动不都等于脚滑：动态物体接触需用相对物体速度，静态地面支撑单独统计。

“脚步不退步”作为采用门槛：相对固定红色参考，总体及各角色的脚滑点估计不得增加，不能用朝向收益抵消；同时报告按录制配对区间和最差序列，区间不能排除退化时记为证据不足。相对原55k的足部代价也必须另列，不能仅证明优于已经退化的红色。穿透、边界跳变或角速度尖峰增加也不通过。后续若设容差，需在看新结果之前记录，不沿用过去“最多5%”就宣称不退步。

每轮先记录假设、唯一改动、基线、身份/种子、权重与代码指纹及通过条件，再运行；失败也入表，不更新演示为默认成功版。源数据/缓存保留，新训练仅一个last.pt，不建编号/全顶点副本。当前本轮只做审计与方案收敛，没有新增训练或checkpoint。
