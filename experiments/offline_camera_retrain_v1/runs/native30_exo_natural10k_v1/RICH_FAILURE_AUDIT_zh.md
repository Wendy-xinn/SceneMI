# RICH EXO 8k 失效核查

本次只读取既有 VAL 的输入、GT、reference、control 与各 checkpoint 输出，以 CPU 重算关节/旋转；没有启动新训练或 GPU 评估，没有修改封存源码。面板与源码 SHA256、逐窗配对指标见 `RICH_FAILURE_AUDIT.json`。这不是完整 VAL/TEST 的结论。

**结论：现有 8k 在 RICH 存在真实的带噪遮挡恢复退化，不能只用“采样少，再训一阵”解释。暂未发现该错例的坐标/帧对齐或参考构造不一致。**

| 面板/输入 | 隐藏误差 reference→8k (mm) | 比输入更差 |
| --- | ---: | ---: |
| 固定 / clean | 36.23 → 40.40 | 8/11 |
| 固定 / noisy | 60.06 → 115.08 | 9/12 |
| 轮换8k / clean | 56.12 → 59.39 | 5/12 |
| 轮换8k / noisy | 89.01 → 94.21 | 4/12 |

按窗口等权、空隐藏掩码排除。固定 noisy 可见关节误差仍从36.02降到31.16mm，说明不是整个人完全没学会；但看不见的关节被生成器改坏。8k时自然采样已覆盖所有394个RICH训练窗口至少4遍，占比2.57%不等于没见过。

## 明确错例：Pavallion_006_yoga1，起始640帧

| 适配步数 | clean 隐藏(mm) | noisy 隐藏(mm) |
| --- | ---: | ---: |
| control | 103.5 | 423.1 |
| 2k | 447.9 | 587.1 |
| 4k | 74.8 | 582.2 |
| 6k | 75.3 | 591.5 |
| 8k | 88.9 | 594.6 |

该窗口的 noisy reference 本来95.3mm，8k为594.6mm；扣除root平移后仍从97.0增到564.6mm，因此不是仅仅整个人平移/场景坐标偏了。右踝70.9→941.2mm，右脚81.5→1012.6mm。该单窗贡献固定noisy退化差值的约76%；去掉它后仍约56.86→71.49mm。

右踝/脚整个192帧都不可见，右膝位置全程可见。参考构造在没有观测后代时，将右膝local rotation设为单位阵、旋转置信度0.05；实际GT右膝local角中位8.2°、最大30.3°，因此参考直腿本身尚可。8k clean右膝角中位7.9°，noisy却达到156°，是一整段平滑的错误折腿，不是逐帧抽搐。

`native30_observation_ik.py:19–24,46` 的IK只用可见后代约束对应旋转。右膝后代全不可见，右膝旋转strength为0，IK不会直接把这个膝关节扭成156°。错误来自生成/场景反馈路径；仅凭最终保存数组，还不能确定两者各占多少。

已核查：clean/noisy用相同DDIM种子；右腿掩码相同；新增缺失只有右肘18–35帧。根部四个观测点全程有效，SVD第二奇异值保持约0.0018以上，无退化拟合翻转。CPU重建reference与已保存结果的最大特征差小于5.1e-6。reference本地右膝始终近0°，没有参考自身180°跳变。噪声除了改位置，还降低confidence、增加uncertainty，根部软锚点有效强度由约0.9降到0.16–0.50；但这不能单独解释155°局部膝角。

## 下一步建议，尚未执行

1. 先核对identity/reference直通、残差零点与低噪x0一致性，并保存同一错例DDIM每步中反馈前、IK前后的右膝local rotation，定位首次翻转。
2. 用同一8k、相同窗口和种子做scene ON/OFF；固定位置只变化confidence/uncertainty；诊断性限制相对reference的局部SO3修正幅度。核查隐藏误差与可见保持，不能只凭“看起来不翻腿”判有效。
3. 再决定是否新训：若确为过度改写参考，测试identity保持样本和置信度相关修正约束；若小样本都拟合不了，先排查梯度/LoRA容量。当前损失含GT的raw_x0、FK和旋转监督，但没有保证输出相对reference误差必然不增的机制。上述措施都需实测，不能承诺有效。
